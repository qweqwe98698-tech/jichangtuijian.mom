拿到订阅之后真正要做的事只有五件,加起来十几分钟。之所以很多人卡了一晚上,不是流程复杂,而是不知道每一步做完应该看到什么——于是某一步其实已经失败了,却还在往下走,最后所有异常堆在最后一步爆发,根本没法回溯。

这篇的写法和常见教程不同:每一步都配一个可观察的**预期结果**。达到了就继续,没达到就停在原地排查,不要往下推进。这个约束比任何技巧都管用。

流程本身跨设备通用。桌面端和移动端的界面文案有差异,但五个环节的顺序和判据完全一致,所以下面刻意不写某一款客户端的按钮位置,那属于[客户端教程栏目](/guides/)的范围。

## 动手之前,先确认哪三件事已经就绪?

有三件事没准备好就开始操作,后面的每一步都会失败得莫名其妙。

1. **付款已经开通**。有的商家付款和开通之间存在处理时间,后台显示套餐已生效才算数,收到付款成功的邮件不等于服务已开通。
2. **套餐还有余量**。到期日在未来、剩余流量不为零。这两项在用户中心首页通常直接显示,看一眼的成本几乎为零,却能省掉后面大半的困惑。
3. **当前网络本身可用**。能打开国内网站,说明基础联网正常。在一个本身就有问题的网络里配置代理,你会分不清是谁的问题。

## 第一步:订阅链接在用户中心的什么位置?

登录商家后台之后,找「我的订阅」「一键订阅」「订阅地址」这类入口,复制那条完整的链接。

这一步最常见的错误是复制错对象。用户中心里通常同时存在三种网址,长得都像链接:

| 类型     | 特征                         | 用途                 |
| -------- | ---------------------------- | -------------------- |
| 订阅链接 | 通常较长,带 token 之类的参数 | 给客户端读取节点配置 |
| 登录网址 | 就是官网首页地址             | 给人在浏览器里打开   |
| 邀请链接 | 带推广标识                   | 拉新用,与配置无关    |

**预期结果**:剪贴板里是一条长链接。把它粘到记事本里看一眼,末尾没有被截断、开头没有多出空格或换行。

如果这条链接你打算长期用,顺带记住一件事:它等同于账号凭证,拿到的人不需要密码就能读取你的全部节点配置,不要发在群里或截图外传。

## 第二步:不同系统该选哪一类客户端?

客户端只需要满足三个条件:支持订阅导入、支持你机场提供的协议、在你的系统上能跑。

| 系统    | 常见选择方向             | 需要注意的点               |
| ------- | ------------------------ | -------------------------- |
| Windows | 图形界面的规则型客户端   | 首次运行可能需要允许防火墙 |
| macOS   | 同类桌面客户端           | 系统会要求授权网络扩展权限 |
| Android | 支持订阅的移动端客户端   | 注意后台省电策略会杀进程   |
| iOS     | App Store 内的代理客户端 | 部分为付费应用,需外区账号  |

不要在第一次配置时就追求功能最全的那款。界面越复杂,可被误触的开关越多,新手最容易在这里把分流规则改坏。

**预期结果**:客户端已安装并能正常打开,主界面上能找到「订阅」或「配置」入口。

## 第三步:导入之后应该看到什么?

在客户端里新增一条订阅,把链接粘进去,点更新或下载,然后等几秒。

**预期结果**:节点列表出现,里面有若干条带地区名的条目,数量与商家页面上标称的规模大致相当。

这一步是整个流程的分水岭。列表出来了,说明网络能访问商家的订阅接口、账户状态正常、链接格式无误——三件事一次性验证通过。列表是空的或者直接报错,那就停在这里,**不要继续往下选节点**,因为此时客户端里根本还不存在节点这个对象。

空列表的排查方向按可能性从高到低:链接复制不完整、套餐已到期或流量耗尽、链接被重置过而你用的是旧的、当前网络无法访问该订阅域名。

## 第四步:第一次该选哪个节点?

先执行一次延迟测试,再选。选择原则和直觉相反——不要挑名字最花哨的那个。

节点名里的信息量很大:地区决定物理距离,倍率决定流量消耗速度,标签则说明它被优化用于什么场景。首次连接建议选一个**低倍率的常规地区节点**,把变量降到最低。带专用标签的节点往往走特殊线路,一旦不通你会分不清是自己配错了还是这条线路本身有限制。

> 倍率是流量计费系数。标注 2 倍的节点,传输 1 GB 会从账户里扣 2 GB。首次测试用高倍率节点,试几次就可能吃掉可观的额度。

**预期结果**:选中的节点显示出一个具体的延迟数值,客户端状态变为已连接,并且系统代理开关处于开启状态。

延迟数值只说明到节点的握手可达,不代表能正常访问网站,这一点在下一步会验证。

## 第五步:怎样验证代理真的生效?

不要看客户端自己说什么。客户端显示「已连接」只表示它认为握手成功,和你能不能上网是两回事。要看的是实际结果,三项都通过才算数:

1. 打开一个能显示当前出口位置的网页,确认显示的地区与所选节点一致。地区对不上,说明流量没走这个节点。
2. 打开一个国内常用网站,确认仍然正常。打不开说明分流规则把国内流量也送进了代理通道。
3. 换一个非浏览器的应用试试。只有浏览器能用,通常是系统代理没有全局生效,或者该应用有自己的代理设置。

命令行用户可以用更直接的方式确认请求是否真的通过代理返回:

```bash
curl -I --max-time 8 https://www.google.com
```

返回状态码说明链路通;超时或连接被拒绝说明请求没能走出去。

**预期结果**:三项全部通过。任意一项不通过,都属于「握手成功但流量没走对路」这一类症状,处理方向是分流规则、系统代理、TUN 模式和 DNS 这四层,和换节点没有关系。

## 五个步骤里最容易卡住的是哪一步?

按实际求助的分布,卡点高度集中在第三步和第五步,而且原因完全不同。

| 卡在哪一步 | 典型现象           | 问题所在的层         |
| ---------- | ------------------ | -------------------- |
| 第三步     | 列表为空、更新失败 | 账户状态或订阅链接   |
| 第四步     | 节点有但延迟测不出 | 节点或本地网络拦截   |
| 第五步     | 能连上但网页打不开 | 客户端分流与代理设置 |

第三步的失败发生在拿配置的阶段,第五步的失败发生在流量转发的阶段,两者中间隔着好几层。把现象归到正确的那一层,是排查效率的关键,[故障排查栏目](/troubleshooting/)按症状做了完整分流。

## 换设备、换客户端时,哪几步要重做?

订阅链接和设备无关,所以不需要重新购买,也不需要联系商家。

- **换设备**:重做第二、三、四步(装客户端、导入、选节点)。第一步的链接直接复用。
- **换客户端、同一台设备**:重做第三、四步。建议把旧客户端的系统代理关掉再装新的,两个程序同时接管网络会互相打架。
- **订阅链接被重置**:重做第一步,并在所有设备上更新订阅地址,旧链接会立即失效。

需要留意商家对同时在线设备数的限制。超出上限的表现常常是随机掉线,看起来很像线路不稳定,实际上是风控在起作用。

## 小结

五个步骤是复制链接、选客户端、导入订阅、选节点、验证生效,每一步都有可观察的预期结果,没达到就停在那一步。第三步节点列表是否出现,是判断账户与链接是否正常的总开关;第五步用出口地区、国内网站、非浏览器应用三项交叉验证,才能确认代理真的在工作。首次连接选低倍率的常规节点,把变量降到最低。换设备只需重做后三步,订阅链接可以直接复用,但它等同于凭证,不要外传。
