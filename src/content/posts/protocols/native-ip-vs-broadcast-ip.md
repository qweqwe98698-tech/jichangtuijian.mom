链路的前两段——入口和跨境——决定的是快不快;最后这一段决定的是能不能用。数据包从落地服务器发出去的那一刻,它带的源地址就是目标网站唯一能看到的身份。网站不知道你在哪,只知道这个地址在数据库里登记成什么样。

于是就出现了那个让人困惑的现象:两个人连同一个"日本 03"节点,一个正常播放,一个被提示地区不可用。带宽、协议、延迟全都一样,差别只在他们被分到了不同的出口 IP,而这两个 IP 在平台的判定库里长得不一样。

这一层和线路质量是彻底解耦的两件事。专线可以配一个信誉很差的出口,便宜的直连也可能挂着一个干净的原生段。搞清楚判定依据,才能知道什么时候该换节点、什么时候换了也没用。

## 原生 IP、广播 IP、住宅 IP 分别怎么定义

三个词不在同一个分类维度上,这也是它们经常被混着说的原因。前两个说的是"注册地与物理位置是否一致",第三个说的是"属于哪种网络类型"。

| 类型    | 定义                                       | 注册地与落地位置 | 典型归属         |
| ------- | ------------------------------------------ | ---------------- | ---------------- |
| 原生 IP | 由本地机构分配、注册地即所在地的 IP        | 一致             | 当地机房或运营商 |
| 广播 IP | 把其他地区的 IP 段通过路由广播到本机房使用 | 不一致           | 段的注册地在别处 |
| 住宅 IP | 民用宽带运营商分配给家庭用户的地址         | 通常一致         | 家宽运营商       |
| 机房 IP | 数据中心持有的地址段                       | 视情况           | 主机商、云服务商 |

广播 IP 的存在有其合理性:机房在本地拿不到足够的地址,就用自己在其他地区持有的段。技术上完全通,访问速度也不受影响,只是它在各类地理数据库里的登记信息会指向那个"别处"。

住宅 IP 和机房 IP 是另一组对照。同一个原生日本 IP,可以是机房段也可以是家宽段,平台对这两者的信任度往往不同。

## 平台到底靠什么判断一个 IP 属于哪里

不是靠单一信号,而是几路信息交叉:

| 判定信号       | 含义                                    | 谁维护                   |
| -------------- | --------------------------------------- | ------------------------ |
| IP 注册记录    | 该地址段登记的组织与国家/地区           | 各地区互联网注册管理机构 |
| ASN            | 该地址属于哪个自治系统,即哪家网络运营者 | 网络运营者自行登记       |
| 地理位置数据库 | 商业机构维护的 IP 到城市的映射          | 多家商业数据源,各不相同  |
| 使用类型标记   | 标记为数据中心、家宽、移动网络等        | 商业风控服务商           |
| 历史行为评分   | 该段过去是否有异常流量记录              | 各平台自建               |

关键在于最后两项由各家平台自己算,且不公开。这就是为什么同一个 IP 在 A 平台判定为日本正常用户、在 B 平台被标成数据中心并拦截——它们用的不是同一套库,权重也不同。

> 网上流传的"某某节点已解锁全部平台"这类说法基本没有可移植性。判定结果与你查询的时点、你的账号历史、你所在的入口路径都有关,别人的结论对你不构成保证。

## 为什么同一节点在不同平台解锁结果不一样

三个原因叠加:

判定库不同。地理数据库之间对同一个 IP 的记录经常有出入,尤其是新分配或刚转手的地址段,更新滞后是常态。

阈值不同。有的平台只看注册地,有的平台还看使用类型标记,后者会把机房段整体降权。这就是为什么"原生但是机房"的 IP 在某些平台照样过不了。

账号维度不同。平台还会看你这个账号一贯的登录地。一个长期在某地登录的账号突然从另一个地区出现,触发的是账号风控而不是 IP 风控,这时换多少个节点都没用。

## 独享和共享对账号风控的影响有多大

大部分机场节点是共享出口:同一台落地机上的所有人共用一个或少数几个出口 IP。这带来一个连带效应——评分是按 IP 段算的,不是按人算的。

| 出口类型      | 你会受谁影响         | 适合的用途               | 代价              |
| ------------- | -------------------- | ------------------------ | ----------------- |
| 共享出口      | 同节点所有用户的行为 | 浏览、普通视频、日常使用 | 评分波动不可控    |
| 小范围共享    | 少数几人             | 中等敏感度的账号服务     | 价格较高          |
| 独享/固定出口 | 只有你自己           | 需要稳定登录地的账号     | 单独付费,通常按月 |

共享出口最典型的翻车方式是:你什么都没做,只是同一个出口下有人跑了大量自动化请求,整段被降权,第二天你就开始频繁遇到验证。这类问题无法通过"我规范使用"来避免。

## 出口 IP 频繁变化会带来什么后果

对纯浏览基本没影响,对账号型服务影响很大:

- 登录状态被中断,需要反复重新验证;
- 平台把频繁的地区跳变识别为异常,提高验证频率;
- 部分服务会把短时间内的多地登录记为风险事件,留在账号历史里;
- 支付、订阅类操作在登录地不一致时更容易被拒。

机场侧造成出口变化的原因通常有两种:落地机器做了负载均衡,把你分配到不同出口;或者原出口被更换。前者可以通过选固定编号的节点缓解,后者只能等或者换节点。

## 哪些场景真的需要原生 IP,哪些完全不需要

| 使用场景               | 对 IP 类型的要求 | 说明                 |
| ---------------------- | ---------------- | -------------------- |
| 查资料、看网页         | 无要求           | 广播 IP 完全够用     |
| 普通视频、软件更新     | 无要求           | 只吃带宽             |
| 有地区限制的内容服务   | 需要注册地一致   | 广播 IP 常被判为异地 |
| 需要长期维持登录的账号 | 需要出口稳定     | 稳定性比"原生"更重要 |
| 对使用类型敏感的服务   | 倾向住宅段       | 机房段可能被整体降权 |
| 大流量下载             | 建议机房段       | 家宽段带宽上限低     |

值得强调的是第四行:很多人以为自己需要原生 IP,实际需要的是**不变的**出口。这两个需求经常被混为一谈,买错了方向就等于白花钱。出口频繁漂移会在 AI 工具上表现得最明显,具体机制见[流媒体与 AI 访问](/unlock/)栏目。

至于线路类型和 IP 类型的关系,这是两个独立维度:专线解决的是传输路径的拥塞问题,IP 归属解决的是被平台怎么看待的问题。一条 IEPL 专线上挂的也可能是广播 IP。这两者的区别在[线路类型说明](/protocols/how-to-choose/iepl-iplc-explained/)里讲得更细。

## 怎么快速自查一个节点的 IP 类型

按这个顺序做,五分钟能得出可用的判断:

1. **先拿到出口 IP。** 连上目标节点后访问任意一个显示当前公网地址的页面,记下这个地址——它是落地服务器的出口,不是入口机的地址。
2. **查注册信息与 ASN。** 看该地址段登记的组织名与国家/地区代码。登记地与节点标称地区一致的,判为原生;不一致的,判为广播。
3. **看组织名判断网络类型。** 组织名是主机商、云服务商的,基本是机房段;是当地知名宽带运营商的,更可能是家宽段。
4. **交叉两到三个查询源。** 不同数据库对同一 IP 的记录可能不同,只查一处容易被单一数据源的滞后误导。
5. **用目标服务本身做终验。** 所有查询都只是间接证据,能不能用最终以你实际要用的那个服务的表现为准。
6. **隔天复查一次。** 确认出口是否稳定。第一次和第二次拿到的地址不同,说明这个节点做了出口轮换。

命令行的查法只有一条,结构如下:

```bash
# 结构示例,地址为占位符
curl https://example.invalid/ip          # 取当前出口地址
whois 203.0.113.10                        # 看注册组织、国家代码与所属 ASN
```

```text
自查记录表
节点名        出口IP        注册国家  ASN组织类型  与标称地区一致  隔日是否变化
日本 03       ___           ___       机房/家宽    是/否           是/否
```

> 这些查询结果反映的是公开注册数据,不等于任何平台的实际判定结论。平台的风控评分不公开,也不接受申诉式核对,把查询结果当参考、把实测当结论,是唯一稳妥的用法。

## 小结

出口 IP 是链路的终点,也是目标网站唯一能看到的身份。原生与广播的区别在注册地与物理位置是否一致,住宅与机房的区别在网络类型,两组维度互相独立。平台用注册记录、ASN、地理库、使用类型标记和历史评分交叉判定,各家权重不同,所以同一节点在不同平台的结果可以完全相反。共享出口下你的体验会被同段其他人拖累,这一点无法靠自己规范使用来规避。多数人真正需要的不是"原生",而是"不变"——先分清这两个需求,再决定要不要为独享出口付钱。想把这套判断用到实际选购上,可以对照[16 家机场的线路与协议规格](/compare/)逐项核对,而不是相信任何"全解锁"的宣传。
