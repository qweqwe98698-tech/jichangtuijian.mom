节点列表是大多数人接触这些术语的第一现场,也是最没有人解释的地方。客户端把订阅拉下来,屏幕上出现几十行「香港 03 | IEPL | 家宽 | 1x」,没有任何说明文字,你只能凭直觉点一个试试。

这些名字并非随手起的。绝大多数机场遵循同一套隐性约定:按固定顺序把几段信息用分隔符串起来,每一段回答一个不同的问题。知道这套约定之后,一行字能读出的信息量会比想象中大得多——它至少告诉你这个节点在哪、走什么路、扣多少流量、适合干什么。

需要先说清楚的前提是:节点名是机场后台里的一个可编辑文本字段,填什么完全由运营者决定。它没有格式校验,没有第三方核对,写错了或者写得夸张一点也不会有任何提示。所以下面这份速查表解决的是「这个词通常指什么」,而不是「这个节点确实是什么」。

## 一行节点名到底压缩了几段信息

把一个典型名字按分隔符切开,通常能得到四到六段。以「香港 03 | IEPL | 家宽 | 1x」为例:

| 位置   | 示例值 | 回答的问题              | 由谁决定           |
| ------ | ------ | ----------------------- | ------------------ |
| 第一段 | 香港   | 落地服务器在哪个地区    | 机房实际位置       |
| 第二段 | 03     | 同地区内的第几组节点    | 机场自行编号       |
| 第三段 | IEPL   | 跨境走哪种路径          | 机场采购的线路类型 |
| 第四段 | 家宽   | 出口 IP 属于哪类网络    | IP 段的注册归属    |
| 第五段 | 1x     | 每消耗 1GB 从套餐扣多少 | 机场的成本折算     |

有些机场会再加一段用途后缀,例如「流媒体」「AI」「下载」;也有些把倍率写在最前面。顺序不是硬性标准,但字段类型基本就是这几类。读的时候不必纠结顺序,认出每一段属于哪一类就够了。

## 地区码和序号,为什么总是排在最前面

地区放在最前是因为它是唯一一个几乎不会有歧义的字段——服务器物理上在哪个机房,这件事骗不了太久,一测就知道。常见写法有中文地名(香港、日本、新加坡)、国际地区码(HK、JP、SG),以及带旗帜表情的混排。

序号的含义要暧昧得多。「香港 01」和「香港 07」之间没有任何暗示的优劣关系,它只是机场内部的分组编号,可能对应不同的物理服务器,也可能只是同一台机器上的不同端口。有一种常见误解是编号越小越好或者越新,这没有依据。

真正值得留意的是**地区数量与分布**。一家机场如果在同一地区堆了二三十个编号,通常意味着它把用户分散到多台机器上做负载均衡,这比只有两三个节点、全部用户挤在一起要健康。反过来,地区列表铺得极广、每个地区只有一个节点的,往往是靠转售拼出来的资源池。

## 0.5x、2x 这些倍率,扣的到底是什么

倍率是节点名里最容易被误读的字段,因为它长得像折扣,实际却是**流量计费系数**。

| 倍率写法    | 消耗 1GB 实际扣除 | 常见挂在什么节点上               |
| ----------- | ----------------- | -------------------------------- |
| 0.2x / 0.5x | 0.2GB / 0.5GB     | 直连、普通中转、低成本落地       |
| 1x          | 1GB               | 常规中转,机场的基准线            |
| 1.5x / 2x   | 1.5GB / 2GB       | 专线、优质原生 IP 出口           |
| 3x 及以上   | 3GB 起            | 稀缺资源,如部分住宅 IP、特定地区 |

倍率的存在逻辑很直白:机场为不同线路支付的成本相差好几倍,如果一律按 1:1 扣流量,用户会全部涌向成本最高的节点。用系数把成本差异传导给用户,是这个行业通行的做法。

这带来一个实际的计算问题:**套餐标价除以标称流量,算出来的单价没有参考价值**。假如一份套餐标 100GB,而你日常只用 2x 的专线节点,实际能用的就是 50GB;如果混着用 0.5x 的直连看视频、用 2x 的专线开会,那得按使用比例加权算。这一步在[判断专线溢价划不划算](/protocols/how-to-choose/dedicated-line-worth-it/)时是绕不开的,后面那篇里有完整的折算方法。

> 有些机场只在商品页写倍率、节点名里不写,也有些反过来。两处对不上时以后台流量明细为准——用固定节点跑一个已知大小的文件,看扣了多少,这是唯一不会被文案影响的验证方式。

## BGP、CN2、GIA:哪些是线路,哪些只是营销

这一组缩写最容易混,因为它们描述的根本不是同一件事。

| 标签               | 实际含义                                          | 属于哪一层 |
| ------------------ | ------------------------------------------------- | ---------- |
| BGP                | 入口机器同时接入多家运营商,由路由协议动态选路     | 接入方式   |
| CN2                | 中国电信的下一代承载网,与普通 163 骨干网分开      | 线路产品   |
| GT / GIA           | CN2 内部的两个等级,GIA 优先级更高、拥堵时保障更好 | 线路等级   |
| 移动 / 联通 / 电信 | 该节点优化的目标运营商                            | 优化方向   |
| IEPL / IPLC        | 运营商的企业跨境专线产品                          | 线路类型   |

把这张表读顺了,「BGP 中转」和「CN2 GIA 中转」的区别就清楚了:前者说的是入口怎么接,后者说的是跨境走哪条骨干网。两者可以同时成立,一个节点完全可能既是 BGP 接入、又走 CN2 GIA。

需要警惕的是等级词被泛用的情况。GIA 是有明确产品定义的电信线路等级,但节点名里写「GIA」不需要任何证明。判断方法在[线路真实性的五种自测手段](/protocols/how-to-choose/verify-line-and-ip/)里有具体操作——核心是看回程路由的 AS 路径,而不是看名字。

## 家宽、原生、住宅,这三个词说的是同一件事吗

不完全是,但它们都在描述**出口 IP 的身份**,而不是速度。

「原生」指 IP 的注册地与节点所在地一致,例如日本节点用注册在日本的 IP。与之相对的是广播 IP:把其他地区的 IP 段广播到本地机房使用,物理位置在 A 地、注册信息写着 B 地。平台判定归属时看的是注册信息和 ASN,所以这两类在解锁结果上可能完全不同。

「家宽」和「住宅」基本同义,指 IP 属于民用宽带运营商的地址段,而不是数据中心。它的价值在于风控判定——很多平台会把数据中心 IP 段标记为高风险,家宽 IP 则被当作普通用户。代价是带宽上限低、并发能力弱、稳定性受实际住宅线路影响,拿来跑大流量下载往往不如机房节点。

「独享」「专属」这类词描述的是同时使用这个 IP 的人数。共享 IP 上只要有一个人触发了平台风控,同一出口的其他人可能一起受影响;独享 IP 规避了这个问题,价格自然也不同。

> 这三类标签的实际效果高度依赖具体平台的策略,而且平台策略随时会变。任何写在节点名里的「解锁 XX」都只是运营者在写这行字时的观察结果,不构成持续有效的承诺。

## 名字里写着 IEPL,就一定是专线吗

IEPL 和 IPLC 原本是电信运营商面向企业销售的跨境专线产品名。这类电路不经过公网国际出口,因此不受晚高峰拥堵影响,租用成本远高于普通中转带宽——这也是为什么真专线节点的倍率普遍在 1.5x 以上。

问题在于,这两个缩写没有商标保护,没有认证机构,没有任何机制阻止一个普通中转节点被命名为「IEPL 专线」。行业里确实存在几种介于中间的情况:租用他人转售的专线切片、只在部分时段走专线、或者干脆是一条质量较好的公网中转。

识别的思路是看**表现特征**而不是名字。真专线的典型特征是延迟曲线极其平坦,白天和晚高峰的差异很小,抖动幅度通常在个位数毫秒;而公网中转即便平时表现不错,晚八点到十一点之间的延迟波动也会明显放大。这个判断需要跨时段采样才成立,单次 ping 说明不了任何问题。

## 实验、备用、下载专用,这些后缀该怎么用

用途后缀是机场给出的使用建议,读法各有讲究。

1. **实验 / 测试**:通常是新采购或新配置的线路,随时可能调整或下线,不要拿它承载长期任务,更不要绑定需要固定 IP 的账号。
2. **备用 / 应急**:带宽或成本受限的冗余节点,主力节点故障时顶上,平时挂着会挤占本来就不宽裕的资源。
3. **下载 / BT**:允许高并发大流量的节点,通常倍率较低、线路较普通,适合跑大文件,不适合开会和游戏。
4. **流媒体 / AI**:出口 IP 经过针对性挑选的节点,一般倍率更高,建议只在实际需要时切过去,平时用基础节点。
5. **游戏 / 低延迟**:优化方向是延迟和抖动而非吞吐,拿来下载会觉得慢,那是设计取舍不是故障。

按用途分流的意义不只是体验更好,还能省流量:把日常浏览放在低倍率节点上,只在需要时切到高倍率节点,同一份套餐能用的时间会拉长不少。客户端的规则分流可以把这件事自动化,具体做法在[客户端教程](/guides/)里。

## 名字和实际表现对不上,先查哪一步

发现「IEPL 节点晚上照样卡」「原生 IP 节点解锁失败」时,按这个顺序排查最省时间。

1. 先确认自己确实连在那个节点上——客户端的规则分流可能把这个请求分到了别的节点,看实时连接列表而不是看你点了哪个。
2. 再确认问题不是本地的——换个网络环境(比如手机热点)复现一次,如果换了网络就正常,那是本地接入侧的问题,和节点标签无关。
3. 然后做跨时段采样——同一个节点在不同时段各测几次,单点数据不能区分「线路差」和「刚好赶上抖动」。
4. 最后才是核对标签本身——查落地 IP 的 ASN 与注册地,看回程路由的 AS 路径,拿证据对照名字里的声明。

前三步排除掉的往往比第四步多。真正确认是标签与事实不符之后,合理的动作是把节点名当作参考信息而非承诺,并在续费决策里给这家机场的自我描述打一个折扣。完整的验证流程在[五种线路自测方法](/protocols/how-to-choose/verify-line-and-ip/)那篇里,包含可以直接抄用的记录表。

## 小结

节点名是几段信息的拼接:地区和序号说位置,BGP/CN2/IEPL 说路径,原生/家宽/独享说出口 IP 身份,倍率说计费,后缀说用途。这套约定行业通用,但每个字段都由机场自行填写,没有任何认证机制。读懂标签的价值在于快速筛选和按用途分流,而不是把它当成技术凭证。倍率是最值得优先算清楚的字段,它直接改变套餐的真实单价。名实不符时,先排除本地和分流因素,再用跨时段采样和 ASN 核对拿证据。
