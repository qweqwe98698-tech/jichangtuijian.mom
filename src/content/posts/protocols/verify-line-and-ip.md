节点名上写着「IEPL 专线」「日本原生」,商品页写着「BGP 入口、三网优化」。这些描述有没有第三方在核对?没有。整个行业不存在线路认证机制,所有标签都是运营者自己填进后台的文本。

这不意味着标签一定是假的,而是意味着它的性质是**商品描述**,不是技术凭证。判断真伪的责任落在买家身上,好消息是这件事的门槛比想象中低:五种方法都不需要专业设备,一台电脑加半小时就能跑完一轮,难的地方只在于坚持跨时段重复。

下面这套流程的设计目标是**可复现**——同样的步骤,不同的人在不同时间做,得到的数据格式一致、可以互相对照。看不懂节点名里那些缩写的话,先去[节点名称逐段拆解](/protocols/how-to-choose/line-name-decoder/)把术语过一遍,这里默认你已经知道 IEPL、BGP、原生 IP 分别指什么。

## 动手之前需要准备什么

工具清单很短,关键是记录方式要先定好,否则测到第三天就会发现前两天的数据没法对齐。

- **命令行工具**:Windows 自带 `tracert` 和 `ping`;macOS、Linux 建议装 `mtr`,它把路由追踪和持续探测合成一个界面,更适合观察抖动。
- **IP 归属查询**:任意一个公开的 ASN 查询站点即可,重点是它要能同时显示 ASN 名称、注册国家和 IP 类型。
- **记录表**:字段在后面给出,用表格软件或纯文本都行,但必须记录**测试时间**,没有时间戳的数据基本作废。
- **对照组**:至少准备一个已知类型的节点作为参照。手里只有一个节点时,任何数字都缺乏比较基准。

> 开始前先关掉客户端的规则分流,改成全局代理并锁定单个节点。分流规则会把测试流量分到别的出口,这是自测里最常见的数据污染来源。

## 第一步:回程路由能看出什么

去程路由(你的设备到境外服务器)由你这一侧的接入运营商决定,换一条宽带结果就变;**回程路由**(境外服务器返回你设备)由机场采购的线路决定,晚高峰的拥堵也主要发生在这一段。所以判断线路类型,回程比去程有价值得多。

操作顺序:

1. 先查到自己当前的公网 IP,不经过代理直接访问任意 IP 查询页面即可,记下来。
2. 找一个提供回程路由测试的公开工具,或者在自己能登录的境外服务器上执行路由追踪,目标填第 1 步记下的 IP。
3. 记录跨境那一跳之后出现的 AS 编号序列,这串编号就是数据回来时经过的运营商路径。
4. 把结果和节点名的标称对照——标称走电信优质线路,回程却全程公网骨干,两者就对不上。

```bash
# macOS / Linux:持续观察路由与每跳丢包
mtr -r -c 100 <目标IP>

# Windows:查看路由跳数与各跳延迟
tracert <目标IP>
```

读结果时抓两个信号就够了:**跳数**和**AS 路径**。跨境段跳数少、AS 数量少,通常意味着路径更专用;跨境后在多个公网骨干 AS 之间反复横跳,基本可以判定走的是普通公网。真正的专线在追踪里往往表现为跨境段几乎不可见——中间节点不响应探测,直接从境内跳到落地。

## 第二步:落地 IP 的身份对得上吗

这一步核对的是链路终点,决定了各类平台把你判定成哪里的用户。

1. 连上待测节点,访问 IP 查询站点,记下出口 IP。
2. 记录该 IP 的 **ASN 名称**、**注册国家**、**IP 类型**(数据中心 / 住宅 / 商业)。
3. 和节点名比对:标称「日本原生」,注册国家却是其他地区,说明是广播 IP 而非原生 IP;标称「家宽」,类型却是数据中心,同样对不上。
4. 多次断开重连,看出口 IP 是否变化。频繁变化的出口会显著提高账号风控概率。

| 核对项         | 数据来源      | 与什么标称对照          |
| -------------- | ------------- | ----------------------- |
| 出口 IP        | IP 查询站点   | 节点名的地区段          |
| ASN 名称       | 同上          | 「家宽」「住宅」标签    |
| 注册国家       | 同上          | 「原生」标签            |
| IP 类型        | 同上          | 数据中心 / 住宅声明     |
| 重连后是否变化 | 断开重连 3 次 | 「独享」「固定 IP」声明 |

> 查到 ASN 属于数据中心并不等于被骗——绝大多数节点本来就在机房里,这是常态。只有当节点名明确标称家宽、住宅或原生,而查询结果对不上时,才构成描述与事实不符。

## 第三步:延迟曲线怎么区分中转与直连

单次 ping 的数值几乎没有信息量,有信息量的是**一段时间内的形状**。持续探测三到五分钟,观察三个量:平均延迟、抖动幅度、丢包分布。

| 曲线特征                     | 通常对应的线路类型 | 判断依据                  |
| ---------------------------- | ------------------ | ------------------------- |
| 延迟平稳,抖动极小,几乎不丢包 | 专线或高质量中转   | 路径独占,不与公网流量竞争 |
| 延迟中等,规律性小幅波动      | 普通中转           | 入口稳定,跨境段共享带宽   |
| 延迟低但周期性尖峰           | 公网直连           | 骨干网拥塞时排队          |
| 延迟高且丢包成串出现         | 拥堵或被限速       | 队列溢出或策略限速        |

```bash
# 连续探测并保留时间戳,便于事后比对不同时段
ping -c 200 <节点IP> | tee ping-$(date +%m%d-%H%M).log
```

这里的关键不是记住哪种曲线对应哪种线路,而是**同一节点自己跟自己比**。白天平坦、晚上锯齿,说明跨境段与公网流量共享;全天候平坦,才是专线的典型特征。上表里的对应关系是常见倾向,不是判定标准,不同机房、不同接入条件都会让曲线走样。

## 第四步:分时段抽测,为什么少不了

线路差价的绝大部分,买的就是晚高峰那三个小时。白天测出来的数据再漂亮,也回答不了「晚上八点开会会不会掉线」这个问题。

抽测的安排可以很简单:

1. 每天固定三个时间点——上午、下午、晚八点到十一点之间,各跑一次前三步。
2. 至少连测三天,包含至少一个周末,周末的流量分布和工作日不同。
3. 每次都记录时间戳,并用同一个目标地址,换目标地址会让数据失去可比性。
4. 计算晚高峰相对白天的**劣化幅度**,而不是只看绝对数值。

劣化幅度是这一步唯一真正重要的产出。举个说明算法的例子(数值仅为示例,不代表任何机场的实测结果):某节点白天平均延迟 60ms、晚高峰 65ms,劣化约 8%;另一节点白天 45ms、晚高峰 120ms,劣化超过 160%。第二个节点白天的数字更好看,但显然不适合承载晚上的会议。

## 第五步:可用性检测该怎么读结果

前四步测的是链路质量,这一步测的是**实际能不能用**。做法是在你真正需要的平台上逐个试一遍,而不是依赖任何第三方的批量检测脚本给出的对错标记。

- 分平台记录:同一个节点在不同平台上的结果可能完全不同,合并成一个「解锁 / 不解锁」的结论会丢掉关键信息。
- 区分失败类型:是提示地区不可用,还是要求额外验证,还是干脆连不上?三者的成因完全不同。
- 注意时效性:平台的判定策略随时会变,今天可用不代表下个月可用,这一栏的数据保鲜期最短。
- 关注一致性:同一节点连续三天结果一致,才有参考价值;时好时坏通常说明出口 IP 是共享的。

> 各平台的可用性由平台自己的风控策略决定,机场无法控制,也不应被视为承诺。想了解具体平台看重什么,可以去[流媒体与 AI 访问](/unlock/)栏目按平台查。

## 一张可以反复用的记录表

把五步的产出收在一张表里,换机场、换套餐时直接复用。字段刻意保持精简,填不满的宁可留空也不要编。

| 字段            | 填什么                   | 来自哪一步 |
| --------------- | ------------------------ | ---------- |
| 测试时间        | 年月日 + 时段            | 全部       |
| 节点名标称      | 原样抄节点名             | —          |
| 回程 AS 路径    | 跨境后的 AS 序列         | 第一步     |
| 出口 IP / ASN   | IP 与 ASN 名称           | 第二步     |
| 注册国家 / 类型 | 国家 + 数据中心或住宅    | 第二步     |
| 平均延迟 / 抖动 | 两个数值                 | 第三步     |
| 丢包率          | 百分比                   | 第三步     |
| 晚高峰劣化幅度  | 相对白天的百分比         | 第四步     |
| 平台可用性      | 按平台分行记录           | 第五步     |
| 结论            | 与标称一致 / 存疑 / 不符 | 综合       |

填满三天之后,这张表能回答的问题包括:标称与事实差多少、晚高峰能不能扛住、出口 IP 稳不稳定。这三项正好是[判断专线溢价值不值](/protocols/how-to-choose/dedicated-line-worth-it/)所需要的全部输入。

## 哪些结论不能只凭一次测试下

- **「这家机场线路假」**:单节点、单时段的异常可能是临时故障或路由抖动,至少覆盖多个节点、多个时段再说。
- **「速度慢是线路问题」**:本地接入、客户端配置、系统时间偏差都可能造成同样的症状,先按[故障排查](/troubleshooting/)的顺序排除本地因素。
- **「这个 IP 被封了」**:平台的判定会随策略调整变化,间隔一段时间复测比当场下结论可靠。
- **「换协议就能解决」**:协议影响的是能否顺利建立连接和弱网表现,带宽上限由线路决定,把慢归因给协议往往会绕远路。

还有一条容易忽略的:**别人的测试结果对你没有参考价值**。接入运营商、所在城市、宽带类型、测试时段任何一项不同,数据就不可比。这也是这篇文章给的是方法而不是数字的原因。

## 小结

线路标签是自我声明,验证责任在买家,但门槛不高。回程路由看跨境路径,ASN 与注册地看出口身份,延迟曲线看是否与公网流量共享,分时段抽测看晚高峰的真实劣化,可用性检测看实际能不能用。五步之中最关键的是第四步——差价买的就是晚高峰,白天的数据回答不了这个问题。把结果填进固定格式的记录表,换机场时能直接横向对比,比任何推荐都靠谱。
