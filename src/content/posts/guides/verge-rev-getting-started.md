装完 Clash Verge Rev 第一次打开,界面通常是空的:代理页没有节点,订阅页只有一个加号。很多人这时的第一反应是去拨主界面上最显眼的那个开关,然后发现什么都没发生,或者更糟——浏览器彻底打不开网页了。这不是软件坏了,而是它还没被初始化。图形界面能打开,只说明外壳就绪,真正干活的内核和它需要的系统权限还没到位。

决定后面一切是否顺利的,其实是三件在设置页里完成的事:装系统服务、确认端口没被占用、按自己的使用习惯定下启动行为。这三件事和你买没买机场、买了哪家都没有关系,即使手上一个订阅链接都没有,也应该先做完。做完再导入配置,后续出问题的概率会低一个量级,因为剩下的变量只剩配置本身。

本文只讲「没有订阅时,客户端该被设置成什么样」。如果程序根本打不开、启动就闪退、或者提示缺少运行库,那属于另一类问题,应该去看[客户端打不开时的排查流程](/guides/clash/clash-verge-fails-to-start/),在设置页里反复试开关不会有结果。

## 打开后第一屏该点哪里,不该点哪里

首屏落在代理页,列表空着。此刻唯一正确的动作是切到设置页,而不是在主界面上试探。

1. 进设置页找到服务模式一栏,点安装。这一步向系统注册一个后台服务,是 TUN 模式和后续免授权驻留的前提。
2. 回到设置页顶部,记下当前的代理端口号。它通常是一个四位数的混合端口,后面判断冲突要用到这个数字。
3. 确认系统代理开关处于关闭状态。没有节点时打开它,等于告诉整个系统「所有网页请求都发到这个本地端口」,而那个端口后面接的是空气。
4. 上面三步做完,再去订阅页导入配置。

> 千万不要在没有任何订阅的情况下打开 TUN 模式。TUN 会接管整机流量,而客户端此时没有可用出口,直接结果就是断网——并且你还得在断网状态下摸回这个界面把它关掉。

## 为什么安装系统服务是所有后续功能的前提

Clash Verge Rev 的界面是壳,处理连接的是内核进程。有几类操作普通用户权限做不了:创建虚拟网卡、改写系统路由表、以高权限长期驻留后台。系统服务的作用就是把这些活交给一个以更高权限运行的常驻程序,图形界面只负责下指令。

没装服务时的典型表现是这样的:

| 现象                       | 真实原因               | 处理方式                                |
| -------------------------- | ---------------------- | --------------------------------------- |
| TUN 开关点下去自己弹回来   | 没有创建虚拟网卡的权限 | 先装服务,再开 TUN                       |
| 每次启动都弹一次管理员授权 | 内核靠临时提权直接运行 | 装服务后不再需要反复授权                |
| 服务状态显示未安装或异常   | 安装动作被安全软件拦截 | 临时放行后重装,或以管理员身份重开客户端 |
| 改小端口号后无法绑定       | 低位端口需要更高权限   | 装服务,或换用高位端口                   |

装服务需要一次管理员授权,这是设计如此,不是可疑行为。真正需要警惕的是从非官方渠道拿到的安装包索取权限——安装来源本身的判断标准,在 [Clash 教程总览](/guides/clash/)里有单独说明。

## 代理、订阅、连接、日志四个页签各自解决什么问题

| 页签 | 它回答的问题                        | 什么时候真正用得上         |
| ---- | ----------------------------------- | -------------------------- |
| 代理 | 现在走哪个节点,各节点延迟多少       | 日常切换、某地区访问异常时 |
| 订阅 | 配置从哪来,上次更新是什么时候       | 换机场、节点列表变空时     |
| 连接 | 此刻哪些程序在走代理,命中了哪条规则 | 某个软件没走代理时         |
| 日志 | 内核自己在报什么错                  | 前三项都看不出问题时       |

四个页签的排查价值是递增的。连接页最常被忽略,但它是唯一能直接看到「这条请求命中了哪条规则、进了哪个策略组」的地方。判断分流是否按预期工作,看它比靠猜快得多,相关概念在[分流模式怎么选](/guides/clash/rule-routing/)里展开。日志页则是最后一道:界面上一切正常但就是不通时,报错原文往往已经写在那里了。

## 开机自启与静默启动要不要开

这两项经常被一起打开,但它们管的是不同的事:开机自启决定客户端要不要跟系统一起起来,静默启动决定起来之后要不要弹出主窗口。

- 长期固定在自己的电脑上用:两项都开,配合托盘图标最省事。
- 公司电脑或共享设备:建议都关。开机自动拉起一个会改动系统代理设置的程序,在受管控的环境里容易带来额外麻烦。
- 笔记本经常在不同网络之间切换:可以开自启,但关掉「启动时自动打开系统代理」,免得连上公司内网时代理还挂着。

> 开机自启只保证客户端进程启动,不保证系统代理或 TUN 跟着恢复。这两项是否随启动一并生效,取决于设置里各自独立的开关,别把「自启成功」理解成「配置全都回来了」。

## 端口设置里哪几项新手不要动

和端口有关的设置通常是三项,作用完全不同:

| 设置项         | 作用                                   | 建议                        |
| -------------- | -------------------------------------- | --------------------------- |
| 混合端口       | 同时接受 HTTP 与 SOCKS 请求的本地端口  | 只在冲突时改                |
| 外部控制端口   | 供外部面板或脚本调用内核接口           | 没有明确需求就别动          |
| 允许局域网连接 | 让同网络的其他设备也能用这台机器的代理 | 默认关闭,给自己手机用时才开 |

改端口的唯一正当理由是冲突。判断依据很直接:日志里出现端口绑定失败,或者启动后系统代理里写的那个端口号在别的软件里也被占着。这时把混合端口换成一个不常用的高位数值即可。端口究竟对哪些程序生效,是另一个更重要的问题,[系统代理到底代理了谁](/guides/clash/proxy-mode-and-system-proxy/)那篇专门讲这件事。

下面是这几项在配置文件层面的结构示例,只用于理解对应关系,实际数值以你客户端界面显示的为准,地址部分一律用示例域名:

```yaml
# 结构示例,不是可直接使用的配置
mixed-port: 7897
allow-lan: false
external-controller: 127.0.0.1:9097
# 订阅地址形如 https://example.invalid/subscribe?token=your-token
```

> 允许局域网连接一旦打开,同一 Wi-Fi 下的任何设备都能使用你的代理端口和你的流量。在宿舍、公司、咖啡馆这类共享网络里务必保持关闭。

## 界面语言、主题与托盘图标怎么调

这部分不影响功能,却影响你后面能不能对得上教程。界面语言保持中文即可,遇到英文截图按位置对应就行;主题跟随系统,深色模式下日志页的报错配色区分度反而更好。

托盘设置值得单独花半分钟。把「关闭窗口时最小化到托盘」打开,可以避免误点右上角的叉导致代理直接中断——「刚才还好好的突然全断了」有相当一部分就是这么来的。托盘右键菜单一般能直接切换代理模式和系统代理开关,日常使用比开主窗口顺手得多。

## 首次启动最容易踩的三个坑是什么

1. 没装服务就开 TUN。表现是开关自动弹回,或者开成功了但整机断网。正确顺序永远是先服务后 TUN,该不该开的判断标准见 [TUN 模式什么时候必须开](/guides/clash/tun-mode/)。
2. 没有订阅就开系统代理。表现是浏览器全部转圈,而客户端界面看起来毫无异常。这种情况先关掉系统代理恢复上网,再回头导入订阅。
3. 把关窗口当成了退出。关闭多半只是隐藏;而真的结束进程时,如果系统代理没有被正确还原,又会变成「退出之后反而上不了网」。

三条的共同现象都是「上不了网」,根因却分在三个不同的层。回想一下刚才动过哪个开关,比重装客户端有用得多。配置进来之后的日常维护节奏,可以接着看 [Clash 订阅要多久更新一次](/guides/clash/clash-update-subscription/)。

## 小结

首次启动要做的不是拨开关,而是初始化:装系统服务、确认端口、定下启动行为,这三件事与订阅无关却决定后续一切。四个页签各管一层,代理看节点、订阅看配置来源、连接看规则命中、日志看内核报错,排查时按这个顺序走能省掉大量无效尝试。端口和外部控制这类设置在没有冲突证据前不要动,允许局域网连接则默认保持关闭。把这些做完之后再导入订阅,任何异常都能被限定在配置这一层里。
