订阅是小火箭和机场之间唯一的桥。App 本身不含任何线路,机场也不会主动把节点推给你的手机——中间靠的是一条 HTTPS 地址:小火箭定期访问它,拿回一份节点清单,再解析成你在列表里看到的那几十条。理解了这个流程,导入环节的大部分怪现象都能自己解释。

真正让人反复踩坑的不是操作步骤,而是「加进去的到底是什么」。订阅地址、单节点分享链接、配置文件,三样东西都能被小火箭接受,但接受之后的行为完全不同:只有订阅会随机场增删节点自动变化,另外两样是静态快照,加一次就固定在那里。

## 三样东西长什么样,怎么分辨?

先看形态,再谈导入:

```text
订阅地址        https://机场域名/api/v1/client/subscribe?token=一串随机字符
单节点分享链接   vmess://<一长串 Base64>   trojan://<密码>@<域名>:<端口>
远程配置文件     https://某地址/xxx.conf 或 .module 结尾
```

上面的写法只是形态示例,不是可用配置。分辨的关键在开头:普通网址开头的多半是订阅或配置,协议名加冒号双斜杠开头的一定是单个节点。

| 类型           | 加进去之后       | 会不会自动更新    | 典型来源             |
| -------------- | ---------------- | ----------------- | -------------------- |
| 订阅地址       | 出现一整组节点   | 会,刷新时重新拉取 | 机场用户中心         |
| 单节点分享链接 | 只多出一条节点   | 不会              | 群聊、论坛、他人转发 |
| 远程配置文件   | 带来规则和节点组 | 会,按配置源更新   | 机场提供的专用配置   |

## 方式一:复制链接,让剪贴板识别

复制订阅地址之后切回小火箭,App 检测到剪贴板里有可识别内容时会弹出提示,问你是否添加。这条路径最快,但也最容易出事——它识别的是「剪贴板里的任何可解析内容」,你上一次复制的如果是别人发的单节点链接,它会照样加进来,而且加完之后长得和订阅条目差不多。

弹窗一闪而过没点中的话,不必重新复制,直接换手动新建即可。

## 方式二:在配置页手动新建订阅

这是三条路径里最不容易出错的一条,因为你在填写时就已经明确告诉 App「这是一份订阅」。

1. 进入底部的「配置」标签页,点右上角加号——这一步决定了新增条目的类型是订阅而不是单节点。
2. 在 URL 栏粘贴订阅地址,不要手动补全或删改问号后面的参数,那串 token 就是你的身份凭证。
3. 备注名填成能认出来的名字,例如按机场缩写加套餐月份——同时用两三家机场时,这个习惯能省掉大量翻找。
4. 保存后回到列表下拉一次,让它真正去访问地址;不刷新的话,条目存在但节点为空。

新建界面里那几个可选开关(是否启用远程配置、是否覆盖本地规则)默认不动即可。它们影响的是规则来源,不影响节点是否能拉下来,首次配置阶段动它们只会增加变量。

## 方式三:机场网页上的一键导入按钮

多数机场的用户中心提供「导入到 Shadowrocket」的按钮,点击后由浏览器唤起 App 并自动填好地址。它的成功率取决于浏览器是否允许唤起外部应用,以及点击时 App 是否已安装。

点了没反应通常是三种情况:用的是微信或 QQ 内置浏览器(拦截了唤起协议)、App 尚未安装、或者系统询问是否打开时被误点了取消。改用 Safari 打开同一页面再点一次,多半就能解决;仍然不行就回到方式二手动粘贴。

## 三种入口该怎么选?

| 入口         | 操作成本 | 误加单节点的概率 | 后续可自动更新           | 适合谁                         |
| ------------ | -------- | ---------------- | ------------------------ | ------------------------------ |
| 剪贴板识别   | 最低     | 较高             | 是(前提是加的确实是订阅) | 已经熟悉三种链接形态的人       |
| 手动新建     | 中等     | 最低             | 是                       | 第一次配置、同时管理多家机场   |
| 网页一键导入 | 低       | 中等             | 是                       | 机场提供了按钮且用 Safari 打开 |

结论其实很朴素:第一次配置就老老实实走手动新建,确认整条流程无误之后,再用更快的入口。

## 导入成功该看哪三个信号?

只看到列表里有东西并不等于成功。三项一起对上,才算这一步真正过关:

- **节点数量对得上**。和机场页面标注的节点数大致一致即可,少几条通常是协议兼容问题——较新的 UDP 类协议需要更高版本的 App 才能解析,这不是订阅坏了。
- **流量与到期日有显示**。这些数字来自订阅响应里的附加信息,机场没返回时会长期空白,属于机场侧的输出差异,不影响节点可用。
- **延迟测试有结果**。点一次测试,能测出毫秒数说明握手成功。要注意这只代表通得到,不代表带宽足够。

> 三项都正常但网页仍然打不开,问题已经不在导入环节了。这类「握手成功但数据不通」的现象,排查线索在 DNS、路由模式和节点是否假存活,详见 [小火箭连上了但不能上网的排查顺序](/guides/shadowrocket/shadowrocket-connected-no-internet/)。

## 一部 iPhone 能放几个机场的订阅?

数量上没有硬性限制,配置页可以并存多条订阅,节点会汇总在同一个列表里。代价是列表变长、名字容易混,所以备注名的命名习惯值得从第一天就立起来。

同时留两家机场是不少人的做法:一家日常用,一家备用,某一家线路波动时立刻切换,不必临时找服务、临时付款。真要评估该留哪一家,可以到 [机场评测栏目](/reviews/) 对照各家公开的套餐与线路规格再决定。

## 订阅链接为什么绝对不能截图发出去?

那串 token 就是你的身份。任何人拿到这条地址,都能在自己的设备上导入同一份节点,消耗的是你的套餐流量,占用的是你的设备数上限。更棘手的是,机场看到的只是「同一份订阅在多地使用」,异常时被限制的是你的账号。

在群里求助时,截图前务必把地址那一行遮住;直接把二维码发出去也是同样的问题,二维码里装的就是这条地址。发现疑似泄露,到机场后台重置订阅地址,旧链接会立刻失效,重置后记得回到 App 把旧条目删掉重加。

## 小结

导入订阅的核心不是找到按钮,而是确认加进去的确实是一份订阅而非单条节点。手动新建最稳,剪贴板识别最快但容易混,网页一键导入受浏览器限制。加完必须下拉刷新一次才会真正拉取节点,再用节点数、流量信息、延迟测试三项交叉确认。订阅地址等同账号凭证,截图和转发前一定遮住。
