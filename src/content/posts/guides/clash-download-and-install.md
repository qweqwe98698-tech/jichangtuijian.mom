搜索「Clash 下载」得到的结果往往互相矛盾:有的教程截图是深色卡片式界面,有的是老式三栏布局,有的干脆推荐一个从没听过的名字。这不是教程写错了,而是「Clash」这个词在今天并不指向某一个具体软件。

它最初是一个用 Go 语言写的开源代理内核,职责是读配置文件、建连接、按规则分发流量,本身没有任何界面。原始仓库停止维护后,社区分叉出以 Mihomo 为代表的新内核;不同团队又在内核外面套上图形界面,才有了能点鼠标的客户端。你真正要下载的,是这些客户端里的某一个。

搞清这层关系有实际好处:你会知道哪些教程的截图和你对得上、遇到问题该去哪个项目的 issue 里搜、以及为什么换客户端不需要重新申请订阅。这篇只解决装哪个、从哪装、怎么装上三件事,内容停在客户端第一次成功启动的那一刻。

## Clash、Mihomo 和 Clash Verge Rev 到底是什么关系

可以用三层来理解。最底下是内核,负责实际的网络工作;中间是配置文件,一份 YAML 文本,规定有哪些节点、按什么规则分流;最上面是图形客户端,提供按钮、开关和节点列表。

Mihomo 是内核这一层的主流选择,它由早期的 Clash.Meta 更名而来,支持的协议比原版内核更多。Clash Verge Rev 则是客户端这一层的程序,它内部调用 Mihomo 完成实际工作。所以「装 Clash Verge Rev」这个动作,等于同时装了界面和内核。

> 配置格式在这几层之间基本通用。这意味着换客户端时订阅链接可以直接复用,不需要向机场重新申请。

## 原版 Clash for Windows 停更之后还能不能用

已经装在机器上的老版本通常还能启动,也还能连上一部分节点。但项目早已停止维护,新出现的协议不再支持,安全问题也不会有人修。继续用它的实际代价是:某天机场升级线路后,你的客户端突然连不上,而这个问题永远不会有更新来解决。

迁移成本很低——装新客户端、粘贴同一条订阅链接,十分钟的事。没有理由为一个停更的程序保留风险。

## 四类设备分别该装哪一个

| 设备         | 推荐客户端                       | 内核   | 说明                                                       |
| ------------ | -------------------------------- | ------ | ---------------------------------------------------------- |
| Windows      | Clash Verge Rev                  | Mihomo | 支持系统代理与 TUN,安装时会一并注册系统服务                |
| macOS        | Clash Verge Rev                  | Mihomo | 注意区分 Intel 与 Apple Silicon 两种安装包                 |
| 安卓         | FlClash / Clash Meta for Android | Mihomo | 前者界面更现代,后者更接近原生配置逻辑                      |
| iOS / iPadOS | 无同名客户端                     | —      | 需在 App Store 选择支持同类配置的付费工具,且受账号区域限制 |

iOS 这一行值得单独说明:苹果的审核政策导致这类应用长期不在中国区上架,常见做法是使用其他区域的 Apple 账号购买。这一步涉及账号与支付规则,建议自己核对清楚再决定,本文不展开。

## 官方下载地址怎么认,哪些站点必须绕开

判断标准只有一条:安装包是不是从项目自己的代码仓库发布页拿到的。这类客户端都在 GitHub 上开源,发布页会列出各平台的安装包和对应的校验值。

需要绕开的通常是这几类:排在搜索结果前面的「软件下载站」、承诺免登录高速下载的镜像、把安装包重新打包成「免配置版」的资源站。代理客户端会经手你的全部网络流量,二进制文件被改过一行代码,泄漏的就是明文内容。这不是概率问题,而是后果严重程度的问题。

下载完先算一次哈希再安装:

```powershell
Get-FileHash .\Clash.Verge_x64-setup.exe -Algorithm SHA256
```

macOS 与 Linux 用另一条命令:

```bash
shasum -a 256 ./Clash.Verge_universal.dmg
```

把输出的字符串与发布页公布的值逐位对照,不一致就重新下载,不要抱着「先装上试试」的心态。

## 杀毒拦截和管理员权限该怎么处理

这类客户端被杀毒软件报毒相当常见,原因在于它的行为特征:创建虚拟网卡、修改系统代理设置、注册后台服务——这几项恰好也是部分恶意程序的典型动作。误报不代表软件干净,但也不能反过来当成有问题的证据。

判断顺序应该是:先确认下载来源是官方仓库,再确认哈希一致,两项都通过就可以把安装目录加入杀毒软件白名单。反过来,如果来源本身可疑,那么杀毒软件没报警也说明不了什么。

安装过程需要管理员权限,因为要注册系统服务。跳过这一步的后果不会立刻显现,而是等到开启 TUN 模式时突然报错。装的时候顺手给权限,比事后回来补要省事。

## 装完先做哪三步自检

1. 看版本号——确认启动的是刚装的版本,而不是系统里残留的旧程序,老配置目录经常导致这种混淆。
2. 看内核状态——客户端界面通常会显示内核是否运行中,这一项不正常时后面所有操作都不会有效果。
3. 看系统服务——服务未安装时,普通代理还能用,TUN 模式一定失败,提前确认能省掉一次误判。

三项都正常就可以进入下一环节。把订阅放进客户端的完整操作和成功判据,在[Clash 专题的订阅导入部分](/guides/clash/)里有单独说明。

## 重装之前要不要先清干净旧版本

从老客户端迁移过来的人常遇到一类怪事:新版本装好了,界面却还是旧的样子,或者节点列表里混着早就删掉的配置。原因是这类程序把配置、日志和内核缓存放在用户目录下的独立文件夹里,卸载程序默认不会动它。

处理方式分两种情况。想保留原来的订阅和规则,就直接覆盖安装,配置目录原样留着;想彻底重来,则要在卸载之后手动删掉配置目录,再装新版本。第二种做法能解决大部分「明明重装了问题还在」的状况,代价是订阅要重新导入一次。

> 删配置目录之前先把订阅链接单独存一份。不少人清理完才发现链接只存在客户端里,又得回机场后台重新登录去找。

另外,卸载并不会自动移除已经注册的系统服务,也不会还原系统代理设置。如果卸载后发现网络异常,先去操作系统的代理设置里确认那个指向本机端口的开关已经关掉。

## 版本号、安装包被删这些零碎疑问

版本号带 Beta、Alpha 或 rc 字样的属于预发布版,给愿意帮忙测试的人用,日常使用选没有这些后缀的正式版即可。

安装包下载完就被系统或杀毒软件自动删除,多数是浏览器的安全下载策略在起作用,可以在下载管理里选择保留,或者临时关闭该项策略后重新下载——前提仍然是来源可信。

至于「装完就能用吗」,答案是不能。客户端只是一个空壳,还需要一份配置才能工作。配置从哪来、怎么放进去,是[客户端教程栏目](/guides/)里下一步要解决的事。

## 小结

Clash 是内核、配置与客户端三层结构,你要下载的是最上面那一层。桌面端选 Clash Verge Rev,安卓选 FlClash 或 Clash Meta for Android,原版 Clash for Windows 已停更不建议新装,iOS 需要另找同类工具并注意账号区域限制。安装包只从项目官方仓库获取,装前算一次哈希,装时给足管理员权限。启动后确认版本号、内核状态与系统服务三项正常,这台设备的准备工作就算做完了。
