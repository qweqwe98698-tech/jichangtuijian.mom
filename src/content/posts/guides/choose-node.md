订阅拉下来那一刻,列表里可能有三十条,也可能有一百多条。绝大多数人的第一反应是从头点到尾,哪条快用哪条——这个办法在节点少的时候还行,列表一长就变成纯粹的碰运气。

更省力的思路是把它当成一个漏斗:**用途决定地区,延迟决定可用,倍率决定成本,实际体验决定最终留谁**。四道筛子按顺序过一遍,通常两三分钟就能定下一条主力节点,而且下次遇到问题时你知道该从哪一层重新排查。

需要先破除的是「延迟越低越好」这个直觉。延迟衡量的是一次握手打了个来回花多久,它回答「通不通、绕得远不远」;而你真正在意的卡不卡,取决于这条线路此刻还剩多少带宽可用。两者经常不同向,晚高峰尤其明显——最快的那条往往也是挤得最狠的那条。

## 节点名字里的地区、编号、倍率分别怎么读?

机场的命名没有统一标准,但拆开来看无非几个字段:

```text
# 结构示例,不同机场的写法会有差异
香港 IEPL 01 | 2x
 ^    ^     ^    ^
地区  线路   编号  流量倍率
```

对应的读法:

| 字段     | 常见写法                          | 它告诉你什么                        |
| -------- | --------------------------------- | ----------------------------------- |
| 地区     | 香港、HK、日本、JP、美国、US      | 出口在哪,决定看到的是哪个地区的内容 |
| 线路类型 | IEPL、IPLC、专线、中转、直连、BGP | 跨境路径怎么走,直接影响晚高峰表现   |
| 编号     | 01、02、A、B                      | 同地区的第几台机器,用于分散负载     |
| 倍率     | 0.5x、1x、2x、3x                  | 按几倍从套餐里扣流量                |
| 用途标记 | 流媒体、解锁、Chat、游戏          | 机场声明该节点针对某类服务做过适配  |

带用途标记的节点要理解成厂商声明的适配方向,而不是保证。这类标记通常意味着机场为该节点选了特定归属的出口 IP,但平台侧的判定规则随时会变,能不能用最终仍要以你自己打开看到的结果为准。想理解出口 IP 为什么决定解锁结果,可以看 [原生 IP 与广播 IP 的区别](/protocols/how-to-choose/native-ip-vs-broadcast-ip/)。

## 延迟测试要按哪个按钮,结果多少算正常?

节点列表页顶部或右上角有一个测试按钮,点一次后 App 会对每条节点发起握手并记下往返时间。测试期间保持前台,切走会中断。

数值的合理区间由物理距离决定,不同地区不该用同一把尺子:

| 出口地区     | 常见延迟区间(参考值) | 说明                       |
| ------------ | -------------------- | -------------------------- |
| 香港、台湾   | 几十到一百多毫秒     | 距离最近,中转线路通常最低  |
| 日本、新加坡 | 一百毫秒上下         | 略高于港台,差距不大        |
| 美西         | 两百毫秒上下         | 跨太平洋的物理下限摆在那里 |
| 欧洲         | 两三百毫秒           | 路径最长,不适合做日常主力  |

> 上表是按常见跨境路径推算的参考区间,不是实测数据。你的实际数值受本地宽带、运营商、所处城市和当时链路状况影响,同一节点在不同环境下差几十毫秒完全正常。

比绝对值更有信息量的是波动。同一条节点连测三次,如果数值在几十和几百之间来回跳,说明这条路当下并不稳,即便某一次测出的数字很漂亮也不该选它。测不出结果、显示超时的那些,直接排除即可,不必纠结原因——排查超时是另一套流程。

## 为什么延迟最低的节点不一定最好用?

因为握手和传输走的虽是同一条路,但衡量的是两件事。可以这样对照:

| 指标       | 测的是什么     | 好的时候代表     | 不能说明什么     |
| ---------- | -------------- | ---------------- | ---------------- |
| 延迟       | 一次往返耗时   | 路径通、绕路不多 | 不代表带宽充足   |
| 下载速度   | 单位时间传输量 | 当前可用带宽大   | 不代表连接稳定   |
| 丢包与抖动 | 传输是否连续   | 长时间任务不中断 | 不代表峰值速度高 |

日常上网对延迟敏感,看视频对带宽敏感,而用 AI 工具这类长时间保持连接的场景对丢包和抖动最敏感——一条延迟很低但每隔几分钟断一次的节点,聊天到一半就会卡住。所以最后一道筛子必须是实际体验:选中节点后打开一个视频拉到中段,看是不是秒开、拖动进度条会不会长时间转圈。这一步花二十秒,比反复测延迟有用得多。

## 看流媒体、用 AI 工具、日常浏览各该选哪类节点?

按用途反推地区,是整个流程里砍掉候选最多的一步。

| 使用场景       | 优先地区   | 优先线路类型 | 要额外留意什么                 |
| -------------- | ---------- | ------------ | ------------------------------ |
| 港台影视内容   | 香港、台湾 | 中转或专线   | 出口 IP 归属要与内容地区一致   |
| 面向北美的服务 | 美国、日本 | 专线优先     | 优先选注册地一致的原生 IP 节点 |
| AI 对话类工具  | 美国、日本 | 稳定优先于快 | 长连接不能断,抖动比延迟更关键  |
| 日常网页与搜索 | 香港、日本 | 任意可用即可 | 选低倍率的,别浪费流量          |
| 大文件下载     | 就近地区   | 带宽优先     | 注意倍率,下载最耗流量          |
| 视频会议       | 就近地区   | 中转或专线   | UDP 类线路对丢包更敏感         |

一个常见误区是「用美国服务就必须挂美国节点」。很多面向全球的服务只看出口 IP 所在的国家,日本、新加坡节点同样落在可用范围内,而且延迟明显更低。真正必须严格对应地区的,是那些按地区分发内容的流媒体平台。

## 倍率是什么,选错会多扣多少流量?

倍率是机场用来平衡成本的机制:线路越贵,倍率越高,你走一份流量就要按几份从套餐里扣。

| 倍率 | 走 1GB 实际扣除 | 100GB 套餐可用 | 常见出现位置           |
| ---- | --------------- | -------------- | ---------------------- |
| 0.5x | 0.5GB           | 200GB          | 部分直连或冷门地区节点 |
| 1x   | 1GB             | 100GB          | 标准中转节点           |
| 2x   | 2GB             | 50GB           | 专线、解锁类节点       |
| 3x   | 3GB             | 约 33GB        | 高端专线或稀缺线路     |

把它换算成具体场景更直观:按 1080p 视频常见码率推算,连续看一小时大约消耗一两个 GB;同样一小时,挂在 3x 节点上就要从套餐里扣掉三到六个 GB。这是按常见码率做的估算,实际值随平台和清晰度浮动,但数量级足以说明问题——**日常浏览挂高倍率节点是最不划算的用法**。

> 合理的分工是:低倍率节点跑日常和下载,高倍率节点只在需要它那份解锁能力或专线质量时临时切过去。用完切回来,这个习惯一个月能省下不少流量。

## 自动选择组和手动指定节点,哪种更适合新手?

自动组按延迟或可用性自行挑一条,省去手动切换。代价是不确定性:出问题时你不知道当时走的是哪条,也不知道是不是被切到了高倍率节点上。

对刚配好的人,建议先手动固定一条主力,理由是可归因——网页打不开时,你至少确定变量只有一个。等到你对哪几条好用心里有数了,再用自动组做兜底,把它的候选范围限制在低倍率、同地区的那几条里,而不是整张列表。

节点选定之后如果国内网站也变慢了,那已经不是节点的问题,而是流量分配方式的问题,解法在 [配置、代理、直连三种路由模式的取舍](/guides/shadowrocket/routing-modes/)。另外,列表里始终没出现某几条节点,多半是协议解析的兼容边界,不属于选择范畴,可对照 [订阅刷新与节点增减的解释](/guides/shadowrocket/update-subscription/)。

## 晚高峰卡顿时应该换节点还是换模式?

先换节点,再考虑模式。晚高峰的劣化几乎都发生在跨境那一段,同地区换一条编号不同的机器往往立刻见效;还不行就换地区,港台挤的时候日本常常更空。

如果换了好几条都一样慢,而且国内网站也跟着变慢,那问题多半不在节点身上,而在流量分配——所有流量都被送出国时,国内站点要绕一圈回来,慢是必然的。这时该做的是检查路由模式,而不是继续在列表里翻。想从更底层理解晚高峰差距的来源,可以读 [中转与直连的结构差异](/protocols/how-to-choose/transit-vs-direct/)。

## 小结

选节点是个漏斗,不是逐条试。用途先圈定地区,延迟测试只用来筛掉不通的,节点名里的倍率决定这条线路值不值得日常挂着,最后用打开一个视频来验证带宽。延迟低只说明握手快,晚高峰最快的那条常常也是最挤的那条。低倍率节点跑日常,高倍率节点按需临时切,是最省流量的用法。新手先手动固定一条主力,把变量降到最少,再谈自动切换。
