小火箭首页那一栏叫「全局路由」,它下面的配置、代理、直连三个取值,决定的是同一件事:你手机发出的每一个请求,是被送进节点绕一圈,还是直接走本地宽带出去。这一栏的位置只有一处,影响却覆盖全机所有 App。

很多人把它理解成开关的强弱档——似乎代理比配置「更开」、直连比配置「更关」。这个类比会误导判断。更准确的说法是:**配置档把决定权交给了规则,另外两档则是把规则整体绕开,强制指定一个方向**。前者是判断,后两者是命令。

分清这一点,后面所有场景就都能自己推出来了:为什么日常应该待在配置档、为什么切到代理反而可能更慢、为什么直连档还值得留着 App 开着。

## 首页这几个选项到底改变了什么?

三个取值的行为差异一次列清:

| 取值 | 流量去向         | 规则是否参与判断 | 国内站点表现              | 流量消耗         | 典型用途                      |
| ---- | ---------------- | ---------------- | ------------------------- | ---------------- | ----------------------------- |
| 配置 | 按规则逐条分流   | 参与             | 走本地宽带,正常           | 只有出国部分计入 | 日常长期使用                  |
| 代理 | 几乎全部送进节点 | 被绕开           | 绕境外一圈再回来,明显变慢 | 全部计入套餐     | 临时验证、规则失效时兜底      |
| 直连 | 全部走本地       | 被绕开           | 正常                      | 不消耗套餐       | 对照排查,确认问题是否来自代理 |

注意最后一列的用词:代理档和直连档都写着「临时」。它们不是给你长期驻留的档位,而是排查工具。真正的日常位置只有配置一档。

## 配置模式下,判断走不走代理的依据是什么?

依据是一份自上而下的规则清单。每个请求进来时,小火箭拿它的域名或目标 IP 从上往下比对,命中哪条就按哪条执行,后面的规则不再参与;全部没命中时,由清单末尾的兜底规则决定。

绝大多数机场提供的配置里已经内置了成套的国内域名与 IP 段规则,所以你不需要自己写任何东西就能得到「国内直连、国外走节点」的效果。规则清单大致是这个形状:

```text
# 结构示例,不是可直接使用的规则
DOMAIN-SUFFIX, 某国内域名, DIRECT
IP-CIDR, 某国内地址段, DIRECT
DOMAIN-SUFFIX, example.invalid, PROXY
FINAL, PROXY
```

规则不可能覆盖全部站点,所以偶尔会出现误判:某个境外小众服务没被任何规则命中,落到兜底那一条上;或者某个国内新域名恰好落进了走代理的分支。这类问题的正解是补一条规则,而不是把整个模式切成代理——具体写法在 [分流规则的匹配顺序与自定义](/guides/shadowrocket/rules-and-split-tunneling/) 里。

## 什么时候必须切到全局,什么时候切了反而更糟?

把它当成诊断动作,而不是解决方案:

| 情形                              | 该不该切到代理档 | 原因                                   |
| --------------------------------- | ---------------- | -------------------------------------- |
| 某个境外网站打不开,其他境外站正常 | 该切,用于验证    | 能打开即说明是规则误判                 |
| 某个境外 App 明明连着却提示无网络 | 该切,用于验证    | 部分 App 不走域名规则,直连分支拦住了它 |
| 所有境外站点都打不开              | 不必切           | 问题在节点或连接层,和模式无关          |
| 想让速度更快                      | 不该切           | 国内流量绕一圈只会更慢                 |
| 想让流量统计更准                  | 不该切           | 全部流量计入套餐,消耗反而暴涨          |
| 需要长期使用某个被误判的服务      | 切完记得改规则   | 靠模式兜底是治标,规则才是治本          |

> 切到代理档之后如果问题依旧,基本可以排除分流因素,接下来该查的是节点是否真的可用、连接是否真的建立。这类「显示已连接却上不了网」的现象有独立的排查顺序,参见 [连接失败与无法上网的排查栏目](/troubleshooting/connection-failed/)。

## 直连模式还开着 App 有什么意义?

意义在于保留通道和对照。选择直连时,系统层的 VPN 通道仍然建立着,规则、DNS 处理和请求日志都在正常工作,只是所有流量都被送去了本地出口。

这带来两个实际好处。一是**排除法**:某个国内网站变慢或某个 App 异常,切到直连再试一次,现象消失就说明和代理有关,现象依旧就说明与小火箭无关,一步定位。二是**免去重新授权**:通道一直在,想恢复代理时切回配置即可立即生效,不必再走一次系统的 VPN 授权弹窗。

如果你确实一整天都不需要代理,直接关掉首页开关比停在直连档更省电。直连档的定位是短时对照,不是待机状态。

## 全局路由会不会把国内银行、支付类 App 一起送出去?

代理档下会。这一档不区分应用类型,只要是走网络的请求,都会被送到境外节点再返回。后果分两层:

- **体验层**:国内服务本来就在境内,绕一圈出去再回来,延迟凭空增加,加载明显变慢。
- **账号层**:银行、支付和部分社交类服务会对登录地做校验,出口 IP 突然变成境外,可能触发异地登录提醒、要求二次验证,个别情况下会临时限制操作。

配置档不存在这个问题,因为国内域名和地址段都被规则明确指向了直连。这也是「日常保持配置档」这条建议最实际的理由——它不只是速度问题,更是避免让不该出国的流量出国。

> 如果你的用法本来就需要长时间挂着代理,更稳妥的做法不是切到代理档,而是留在配置档,再针对个别被误判的服务补规则。粗粒度开关一拉到底,总会误伤。

## 切换模式需要重新连接吗,会断流吗?

不需要重新连接,切换即时生效,系统层的通道不会断。但要注意一个容易混淆的现象:**已经建立的连接不会自动改道**。

| 场景             | 切换模式后的表现                |
| ---------------- | ------------------------------- |
| 新打开一个网页   | 立即按新模式走                  |
| 正在播放的视频   | 沿用切换前的路径,直到重新加载   |
| 正在下载的文件   | 通常沿用旧路径,重开任务才会改变 |
| 长时间保持的连接 | 需要断开重连才会切换            |

所以切完之后网页表现变了、视频却没变,不是设置没生效,而是那条连接还没重建。验证时请用新打开的页面来判断,不要用正在运行的任务。

## 怎么快速验证当前模式是否真的生效?

用两个网站做交叉验证,比看任何设置项都可靠:

1. 打开一个境外网站,能正常加载,说明出国方向的流量确实进了节点。
2. 打开一个国内网站,速度和平时一致,说明国内流量走的是本地宽带。
3. 两项同时成立,当前就是正常的配置档状态。
4. 只有第一项成立、国内网站明显变慢,当前多半停在代理档。
5. 只有第二项成立、境外网站全部打不开,要么停在直连档,要么节点本身有问题。

第五种情况里的两种可能,可以再用一次模式切换区分开:切到配置档仍打不开,说明该查节点。节点该怎么挑、延迟数字该怎么读,整理在 [几十个节点该点哪一个](/guides/shadowrocket/choose-node/);想看清整条配置链路上各步骤的先后关系,可以回到 [小火箭全流程专题](/guides/shadowrocket/)。

## 小结

全局路由那一栏里,配置是唯一适合长期停留的档位,它把每个请求的去向交给规则判断。代理档和直连档都是诊断工具:前者用来验证某个服务是不是被规则误判,后者用来验证问题是不是来自代理本身,验证完都应该切回配置。长期停在代理档的代价是国内站点变慢、流量全额计入套餐,还可能触发支付与银行类服务的异地风控。切换即时生效但不改道已有连接,验证时请用新打开的页面。真正需要精细控制某个域名的走向,该动的是规则,不是这个开关。
