一整屏节点全是超时,连一条绿的都没有,这个画面很容易让人当场下结论:机场炸了。但把概率摆出来看,几十台分布在不同地区、不同机房的服务器在同一秒集体失效,远比「你这一台设备出了状况」要罕见。

关键的判断线索是**范围**。个别节点超时是常态,任何服务都会有节点在维护或被封;而**全部**节点同时超时,意味着所有连接都倒在了同一个共同环节上——那个环节几乎一定在你手上这台 iPhone 里,而不是在几十台服务器上。

iOS 的特殊之处在于,它有一批系统级的限制项是 Windows 和安卓客户端上不存在的:后台被压制、蜂窝权限被关、VPN 授权被撤销、时间没有同步。这些开关任意一个出问题,都会让全部节点一起变红。下面按排查成本从低到高走一遍。

## 先分清:全部超时和个别超时是两个问题

| 现象                           | 指向                 | 优先查                    |
| ------------------------------ | -------------------- | ------------------------- |
| 只有一两条节点超时             | 该节点或其机房异常   | 换同地区其他节点即可      |
| 某个地区整组超时               | 该地区线路或落地异常 | 换地区,顺便看机场公告     |
| 全部节点同时超时               | 设备侧或本地网络     | 本篇的五个开关            |
| 全部节点能测出延迟但打不开网页 | 不是超时问题         | 属于假连接,另一条排查路径 |

最后一行要区分开:能测出毫秒数说明握手成功了,那是「连上了但不通」,和本篇的「根本连不上」是两码事,别混着查。

## 第一处:低电量模式和后台刷新

这是最容易被忽略、也最容易验证的一项。低电量模式会压制后台网络活动,而小火箭的隧道本身就是长时间在后台维持的。

它造成的现象很有辨识度:**时好时坏,而且和电量相关**。锁屏放一会儿再打开就全部超时,插上充电器或关掉低电量模式之后又恢复正常。如果你发现问题总在电量掉到 20% 以下时出现,基本就是它。

处理方式是在系统设置的电池选项里关掉低电量模式,同时确认后台 App 刷新没有对小火箭单独关闭。这一步做完立刻重新测速,不需要重启。

## 第二处:蜂窝数据权限

iOS 允许按 App 单独关闭蜂窝数据。这个开关一旦关掉,小火箭在 Wi-Fi 下表现完全正常,一切到移动网络就等同断网——全部节点超时,而且是瞬间超时,连等待的过程都没有。

判断方法就一句话:**换网络试试**。

| Wi-Fi 下   | 蜂窝数据下 | 结论                       |
| ---------- | ---------- | -------------------------- |
| 正常       | 全部超时   | 查蜂窝数据权限开关         |
| 全部超时   | 正常       | 当前 Wi-Fi 有限制,见第五处 |
| 都全部超时 | 都全部超时 | 继续往下排,或看订阅状态    |
| 都正常     | 都正常     | 问题已经解决或是间歇性的   |

权限在系统设置的蜂窝网络里,往下滑到应用列表找到 Shadowrocket 打开即可。顺带一提,如果你还开了「低数据模式」,也建议在排查期间先关掉。

## 第三处:VPN 描述文件被撤销

小火箭要接管流量,必须在系统里安装一个 VPN 配置。这个配置在几种情况下会被系统撤销或失效:系统大版本升级之后、App 被卸载重装、长时间未使用、或者设备上同时装了多个代理类 App 互相抢占。

被撤销时的表现是:小火箭的连接开关**一开就自动弹回关闭**,或者显示已连接但所有节点都测不出延迟。有些情况下会弹出一个要求输入锁屏密码的授权框,漏点了就等于没装上。

处理顺序是:

1. 先在小火箭里手动断开再连接一次,看是否弹出系统授权框,弹出就输入锁屏密码确认。
2. 没有弹框的话,去系统设置的「通用 - VPN 与设备管理」里查看是否存在小火箭的配置项。
3. 配置项存在但连不上,可以删掉它,回到 App 里重新连接一次让它重新安装。
4. 确认同时只有一个代理类 App 处于连接状态,多个同时开会互相顶掉。

> 删除 VPN 配置不会影响你的订阅和规则,那些数据存在 App 内部。这一步的风险很低,不必犹豫。

## 第四处:系统时间没有自动同步

这一项最反直觉,却是真实存在的失败原因。部分协议在握手时带有基于时间的校验,客户端和服务端的时间偏差超过容许窗口,握手就直接失败,客户端只能报超时。

会导致时间跑偏的情况包括:手工改过日期时间(比如为了某个 App 的限时活动)、长时间关机后开机未联网校时、或者时区设成了手动且选错了地方。

处理很简单,在系统设置的「通用 - 日期与时间」里把「自动设置」打开,联网后等它自己校正,再回小火箭重测。

| 协议类型                            | 对时间偏差的敏感度            |
| ----------------------------------- | ----------------------------- |
| 带时间校验的协议(如 VMess 传统配置) | 高,几分钟偏差即可能失败       |
| 依赖 TLS 证书有效期校验的协议       | 中,偏差过大时证书会被判为无效 |
| 不做时间校验的协议                  | 低,但仍可能影响证书验证环节   |

因为不同协议敏感度不同,你可能会看到「大部分节点超时、少数几条还能用」的混合现象,这同样是时间问题的典型信号,而不是那几条节点特别厉害。想了解协议之间这类设计差异,可以看[协议选择专题](/protocols/how-to-choose/)。

## 第五处:当前 Wi-Fi 本身有限制

排完前四项,剩下的可能性落在网络环境上。校园网、公司网、酒店网络和部分公共 Wi-Fi 会对代理流量做限制,常见做法包括封锁非标准端口、阻断 UDP、或者要求先通过网页认证。

两个验证动作,各自能排除一整类原因:

1. **换一个完全不同的 Wi-Fi**。在另一个网络下正常,说明原来那个网络有限制,不是你的设备或订阅的问题。
2. **用另一台手机开热点连过来**。这一步的意义在于:热点走的是另一条运营商链路,如果热点下正常,就把「本地网络限制」这一类彻底坐实了。

如果只有 UDP 类协议全红、TCP 系协议正常,那基本可以确定网络对 UDP 做了限速或阻断,处理方法在[UDP 被限速的判断与回退](/protocols/how-to-choose/udp-quic-blocked/)里有完整流程,结论通常是回退到 TCP 系协议而不是继续调设置。

> 酒店和机场的公共 Wi-Fi 还有一种特殊情况:必须先在浏览器里完成网页认证才放行流量。小火箭开着的时候认证页可能弹不出来,先关掉代理完成认证,再打开就好了。

## 五项都过了还是全红,接下来怀疑谁

到这一步,设备侧的常见因素已经排干净,可以往外走了。按顺序是:

1. **订阅是不是过期的**。列表里全是几个月前的旧节点,那些服务器早就下线了,自然全超时。手动更新一次订阅,看节点是否有变化;更新本身报错的话,按[订阅导入失败的报错分类](/guides/shadowrocket/shadowrocket-subscription-import-failed/)去查。
2. **账号状态是否正常**。流量耗尽或套餐到期,有些机场的处理方式不是拒绝订阅更新,而是让节点全部不可用。
3. **换一台设备验证同一份订阅**。另一台设备也全红,问题就在订阅或服务端;只有这台全红,那还是设备侧,可以考虑重置网络设置。
4. **看机场的公告渠道**。大规模封锁或机房故障通常会有公告,这一步能避免你独自排查一个已知问题。

如果同一份订阅在多台设备、多条网络下都长期全红,而且机场那边也没有说明,那确实是服务端问题。这种情况反复出现时,更换服务比继续排查更现实,可以到[机场评测栏目](/reviews/)对照各家公开的线路规格和运营情况判断。其他类型的连接故障可以在[故障排查栏目](/troubleshooting/)按现象归类。

## 小结

全部节点同时超时是设备侧问题的强信号,不是机场集体失效。iOS 上按低电量模式、蜂窝数据权限、VPN 描述文件、系统时间、当前 Wi-Fi 这个顺序排,成本由低到高,前四项都不需要重启。时好时坏和电量相关的看低电量模式,Wi-Fi 正常蜂窝断的看权限开关,开关一开就弹回的看 VPN 配置,大部分超时少数能用的看系统时间。五项都过之后再更新订阅、换设备验证,最后才轮到怀疑服务端。
