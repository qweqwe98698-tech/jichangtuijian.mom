v2rayN 的参数设置面板第一次打开时容易劝退：几十个选项平铺在几个分页里，没有推荐值，也没有说明哪一项重要。但真正需要在导入订阅之前定下来的只有六项，其余的都可以等到遇到具体需求时再说。

把这六项单独拎出来的理由是它们的作用范围——它们不是某个节点的属性，而是整个客户端的默认行为。内核决定哪些协议能跑起来，端口决定别的软件怎么找到代理，代理模式决定流量是否真的被接管。这三件事没定好，后面无论导入多好的订阅，都可能出现"节点显示已连接、浏览器却没走代理"这类判断不了的中间状态。

下面这张表是全文的骨架。先照着它把六项过一遍，再看每一节的展开理由。

| 设置项       | 面板位置   | 建议值             | 改错的典型表现               |
| ------------ | ---------- | ------------------ | ---------------------------- |
| 界面语言     | 基础设置   | 简体中文           | 只影响可读性，无功能后果     |
| 内核选择     | 内核设置   | 按订阅协议决定     | 某几类节点始终启动失败       |
| 本地监听端口 | 基础设置   | 保持默认           | 其他软件连不上代理端口       |
| 系统代理模式 | 主界面下拉 | PAC 或全局         | 显示已连接但流量未走代理     |
| 开机自启     | 基础设置   | 个人机开、公用机关 | 无自启时每次手动拉起         |
| 日志级别     | 基础设置   | warning            | 出问题时日志里什么线索都没有 |

## 参数设置面板里，哪几项新手必须先改

面板里的选项大致能分三类：影响全局行为的、影响单个节点的、纯粹的外观偏好。上表六项全部属于第一类。

判断某一项是否属于"必须先改"，有个简单标准——改动它之后，是否需要重新验证已有的节点。内核换了要重验，端口换了要重验，代理模式换了要重验；而界面语言、托盘图标样式这类改了不影响任何连接结果，什么时候改都行。

界面语言之所以还是被放进这六项，是因为它影响的是你后续所有操作的确定性。中英文界面的菜单层级完全一致，但字段名对应关系需要你自己在脑子里翻译一遍，排查问题时多一层翻译就多一分误判概率。既然要照着文档操作，就让界面和文档说同一种语言。

## Xray 内核和 sing-box 内核该选哪个

这是六项里唯一一项没有通用答案的——取决于你的订阅里有什么协议。

| 内核     | 覆盖的常见协议                             | 不覆盖的部分               |
| -------- | ------------------------------------------ | -------------------------- |
| Xray     | VLESS、VMess、Trojan、Shadowsocks、Reality | 基于 QUIC 的新协议支持有限 |
| sing-box | 上述协议加 Hysteria 2、TUIC 等             | 个别 Xray 特有的传输层选项 |

实际操作里有三种情况：

1. **订阅里只有 V 系和 Trojan 节点**——用 Xray，配置项最全，社区文档也最多。
2. **订阅里有 Hysteria 2、TUIC 等 UDP 类节点**——需要 sing-box，具体填法见 [Trojan 与 Hysteria 2 的字段对照](/guides/v2rayn/protocol-config-trojan-hysteria2/)。
3. **两类都有**——v2rayN 允许按节点指定内核，把 UDP 类节点单独指过去即可，不必为了少数几个节点把全局内核换掉。

内核选错的表现具有很强的迷惑性：不是全部节点都不通，而是某一类节点全部不通、另一类完全正常。很多人看到"还有节点能用"就默认是那几个节点坏了，去找机场报障，实际上换个内核就好了。协议本身的差别可以顺带看看[协议选择的判断依据](/protocols/how-to-choose/)，能帮你更快分清是内核问题还是协议问题。

## 10808 与 10809 两个本地端口分别在管什么

v2rayN 默认会在本机开两个监听端口，它们提供的是两种不同的代理协议入口。

| 端口  | 协议类型 | 典型使用方                             |
| ----- | -------- | -------------------------------------- |
| 10808 | SOCKS5   | 命令行工具、开发环境、部分游戏加速插件 |
| 10809 | HTTP     | 浏览器插件、需要填 HTTP 代理的桌面软件 |

需要理解的一点是：这两个端口不是"主备"关系，而是同时开放的两个门，走哪个取决于对方软件支持哪种协议。所以填错的表现往往是某一个软件连不上，而其他软件都正常。

不建议改默认值，除非确实端口冲突。判断是否冲突可以在命令行里查：

```powershell
# 结构示例：查看某个端口是否已被其他进程占用
netstat -ano | findstr "10808"
```

如果输出里出现了非 v2rayN 的进程 ID，说明端口被别的软件抢了，此时改成一个 20000 以上的空闲端口即可。改完之后要做一件事——把所有手动填过代理地址的地方同步更新，包括浏览器代理插件、Git 的 proxy 配置、系统环境变量里的 http_proxy。漏掉一处，那个软件就会一直连不上。

## 系统代理设成 PAC、全局还是不启用

这一项决定的是"哪些流量会被送进代理端口"。

| 模式   | 行为                     | 适合场景                       |
| ------ | ------------------------ | ------------------------------ |
| 不启用 | 只开端口，不改系统设置   | 只想给个别软件手动指定代理     |
| PAC    | 按规则脚本判断，国内直连 | 日常使用，兼顾速度与流量       |
| 全局   | 除本地地址外全部走代理   | 排查问题、需要确保流量全部出境 |

日常建议 PAC，理由是国内站点直连既快又省流量。但排查故障时应该临时切到全局——PAC 模式下"某个网站打不开"存在两种可能：代理有问题，或者这个域名被规则判成了直连。切到全局能一次性排除后者，把变量减少一个。

> 系统代理只对遵循 Windows 代理设置的程序生效。游戏、部分命令行工具、某些桌面客户端天生不读这项设置，看起来"没走代理"其实是它们根本不看这个开关。这类程序需要用 TUN 模式接管，两种方式的取舍见[系统代理与 TUN 模式的对比](/guides/v2rayn/tun-mode-and-system-proxy/)。

## 开机自启和自动检查更新要不要打开

这两项的答案取决于机器归谁用，不存在普遍正确的设置。

开机自启：个人常用的台式机、笔记本建议开启，省掉每天手动拉起的动作；公司电脑、共用电脑建议关闭，因为自启会同时把系统代理开关一起打开，别人用这台机器时可能莫名其妙上不了某些内网服务。

自动检查更新：建议开启检查、但保留手动确认。v2rayN 的版本迭代跟协议更新走，长期不升级会遇到新协议节点无法解析的情况。但自动下载并覆盖有风险——升级过程中如果程序正在运行，可能出现文件占用导致的半完成状态。稳妥做法是收到提示后按[下载安装那篇的覆盖流程](/guides/v2rayn/download-and-install/)手动更新。

还有一个容易被忽略的关联项：开启自启后，最好同时确认"启动时最小化到托盘"也是开启的，否则每次开机都会弹出主窗口。

## 日志级别调到什么程度才方便日后排错

日志级别决定了内核输出多少信息。级别从低到高，输出量呈数量级增长。

| 级别    | 输出内容         | 适用时机                   |
| ------- | ---------------- | -------------------------- |
| none    | 不记录           | 不建议使用                 |
| error   | 仅致命错误       | 信息太少，排查时不够用     |
| warning | 错误加警告       | 日常常驻，推荐值           |
| info    | 加入连接建立记录 | 排查连不上、握手失败时     |
| debug   | 全部细节         | 分析协议字段、传输层问题时 |

日常设成 warning 的理由是它在"有线索"和"不刷屏"之间取得了平衡。设成 none 或 error 的代价，会在真正出问题的那天体现出来——你想看日志，结果里面什么都没有，只能把级别调高再复现一次故障，白白多花一轮时间。

反过来，长期开 debug 也不划算。日志文件会持续增长，而且真正有用的那几行会被大量常规记录淹没。合理节奏是：出问题时调到 info，仍看不出来再调 debug，问题解决后调回 warning。

## 配置文件存在哪，换电脑怎么整体迁移

v2rayN 把所有状态都写在程序目录内，这一点是它便于迁移的根本原因。

```text
D:\v2rayN\                  结构示例，实际路径取决于你解压到哪
├─ v2rayN.exe
├─ guiConfigs\              订阅、节点、参数设置都在这里
│   ├─ guiNDB.db
│   └─ config.json
└─ bin\                     内核可执行文件
```

迁移只需三步：

1. **在旧机器上完全退出程序**——确保配置已落盘，内核进程也已结束，避免复制到不一致的中间状态。
2. **复制配置目录**——把存放配置的子目录整体拷走。主程序和内核不必带，新机器上重新下载同版本即可。
3. **在新机器上覆盖**——先按正常流程装好同一版本的 v2rayN 并启动一次生成默认结构，退出后把备份目录覆盖进去，再次启动即可看到全部订阅与节点。

有两项不会跟着迁移过来，需要在新机器上重设：开机自启（写在系统启动项里）和 TUN 所需的虚拟网卡驱动（属于系统级组件）。除此之外，包括节点排序、自定义路由规则在内的内容都会原样恢复。

顺带说一句，这个目录也是最值得定期备份的东西。手动改过的协议字段、调整过的分流规则，重新配一遍往往比重装客户端麻烦得多。

## 小结

六项设置里，内核、监听端口、系统代理模式这三项决定客户端的实际行为，务必在导入订阅前定下来；界面语言、开机自启、日志级别影响的是使用效率与排查效率，按机器归属和使用习惯选即可。内核选错的表现是某一类节点整体失效而非全部失效，这是最容易被误判为节点故障的一项。端口保持默认最省事，一旦改动要同步所有手动填过代理地址的软件。全部确认完之后，把配置目录备份一份，它既是迁移的全部依据，也是日后配置改坏时的回滚点。
