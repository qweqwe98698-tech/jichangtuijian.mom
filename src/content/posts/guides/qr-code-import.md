在小火箭里添加东西有两条通道:文本和图像。文本通道是把一串地址粘进去,你至少能看见自己粘了什么;图像通道则是把一张图交给 App 解码,内容对人眼是不可见的。快是真的快,风险也正来自这个不可见。

需要先建立的一个认知是:二维码只是一个容器。同一个方块图案里,可能装着一条订阅地址,也可能装着一条单节点分享链接,扫描的动作完全一样,结果却差得很远——前者带来一整组会随机场变化的节点,后者只多出一条从此固定不动的线路。绝大多数「扫完只有一个节点」的困惑,原因都在这里。

另一个反直觉的点是:**二维码不会过期**。它是一张静态图片,把里面那串字符原样打印在纸上一百年后也还是同一串。所谓「二维码失效」,失效的从来是背后那条地址,而不是这张图。理解这一点,你就不会再对着旧截图反复扫。

## 扫码入口藏在哪一层菜单里?

入口比很多人想的浅。打开小火箭首页,右上角有两个图标:一个加号,用于手动新建;紧挨着的那个方框状图标就是扫描。点进去即是取景框。

首次点击时系统会弹窗请求相机权限。这里如果误点了拒绝,之后再点扫描图标会出现黑屏或直接无反应,很像 App 坏了。解决办法不在 App 内,而是到系统设置里找到 Shadowrocket 一项,把相机权限重新打开。

> 取景界面里通常还有一个相册按钮和一个手电筒按钮。相册按钮的位置随版本略有变化,找不到时先把屏幕点亮,它一般在取景框的右上角或底部一侧。

## 相册里的二维码截图怎么让小火箭识别?

大多数人拿到的其实是一张截图,而不是一块能显示二维码的屏幕。这时不需要找第二台设备:

1. 把二维码保存进相册,**截图时保留完整的四个角**——二维码的三个角上有定位方块,缺一个就无法解码。
2. 进入小火箭的扫描界面,点相册按钮,首次会请求照片权限,可以只授权选中的照片而不必给全部访问。
3. 选中那张图,解码在本地完成,不需要联网。
4. 识别成功会直接跳到添加界面;识别不了则会静默返回或提示无法识别。

识别失败时,按这个顺序排查最快:图是不是被裁掉了边角、是不是经过多次转发被压缩得发糊、是不是屏幕上叠了别的元素挡住了图案。从聊天软件里另存的图片经常已被二次压缩,回到原始来源重新截一张往往就好了。

## 扫出来只有一个节点,是二维码的问题还是订阅的问题?

都不是问题,是这张码本来装的就是一条节点。判别方法有两个,一个在扫之前,一个在扫之后。

| 判别时机 | 看什么               | 订阅二维码的表现              | 单节点二维码的表现            |
| -------- | -------------------- | ----------------------------- | ----------------------------- |
| 扫描前   | 二维码下方的文字标注 | 写着订阅、Subscribe、导入订阅 | 写着节点名、地区名或线路编号  |
| 扫描前   | 出现的位置           | 机场用户中心的订阅区块        | 聊天群、论坛帖、他人转发      |
| 扫描后   | 编辑页的类型栏       | 类型为订阅,含一条网址         | 类型为具体协议,含服务器与端口 |
| 扫描后   | 保存并刷新的结果     | 列表一次多出几十条            | 列表只多出一条                |
| 长期行为 | 机场增删节点时       | 刷新后跟着变                  | 永远不变                      |

如果扫出来的编辑页里出现了服务器地址、端口、密码这几栏,那就是一条单节点。结构上它长这样:

```text
# 以下为结构示例,不是可用配置
服务器地址   hk01.example.invalid
端口         443
类型         单个节点(非订阅)
```

而订阅的编辑页里只会有一条以 http 开头的网址和一个备注名。这条差别比任何文字描述都直观。

## 二维码提示无效或无法识别通常是什么原因?

把提示按发生的阶段分开看,原因是不重叠的:

| 现象                     | 发生阶段 | 真实原因                   | 怎么处理             |
| ------------------------ | -------- | -------------------------- | -------------------- |
| 取景框一直不响应         | 解码前   | 相机权限被拒               | 到系统设置里重开权限 |
| 相册选图后无反应         | 解码前   | 图被裁角或压缩过度         | 回原始来源重新截图   |
| 提示无法识别             | 解码中   | 图案不完整或不是二维码     | 换清晰原图重试       |
| 识别成功但保存后列表为空 | 解码后   | 没有下拉刷新               | 回列表下拉一次       |
| 刷新后仍为空或报错       | 解码后   | 订阅地址已被重置或套餐到期 | 回机场后台取新码     |

最后一行是最常见也最容易误判的一种。用户看到的现象是「这张码以前能用,现在不行了」,于是反复换角度扫、换手机扫。实际上图案一直被正确解码,问题出在解码后那条地址已经不再返回数据。旧图在这种情况下永远救不回来,只能回后台重新生成。

> 机场重置订阅地址的常见触发原因是地址疑似泄露、或用户自己点了重置按钮。重置后旧地址立刻作废,这是设计如此,不是故障。重置之后记得把 App 里那条旧订阅删掉,否则它会在每次自动更新时反复失败。

## 扫码导入和粘贴链接导入,后续更新行为一样吗?

一样,前提是两者装的是同一类东西。二维码只是地址的另一种载体,解码之后进入的是同一套逻辑——存进去的是订阅就会自动更新,存进去的是单节点就是静态的。

| 导入方式         | 装的内容 | 后续会自动更新吗 |
| ---------------- | -------- | ---------------- |
| 扫订阅二维码     | 订阅地址 | 会               |
| 粘贴订阅链接     | 订阅地址 | 会               |
| 扫节点二维码     | 单条节点 | 不会             |
| 粘贴节点分享链接 | 单条节点 | 不会             |

所以「扫码导入的不会更新」是个流传很广的误解。真正的分水岭是订阅还是单节点,和你用眼睛看还是用摄像头看没有关系。至于更新是怎么被触发的、为什么有时候更新完节点反而变少,那是另一套机制,写在 [订阅刷新与节点增减的解释](/guides/shadowrocket/update-subscription/) 里。

## 别人发来的节点二维码为什么不建议随手扫?

因为你在扫之前无法知道里面写了什么。粘贴文本链接时,那串字符至少摆在你眼前,域名是谁、端口是多少一目了然;二维码把这一切藏进了图案,你按下确认之前唯一能依据的只有对方的一句话。

代理节点的本质是你所有被代理流量的出口。把一台来路不明的服务器设成出口,意味着谁运营它、它记录什么、它有没有在中间做手脚,你全部无从核实。这和「速度快不快」是两个层面的问题。

稳妥的做法只有一条:**只扫自己付费机场后台里的那张码**。别人转发的、群里流传的、帖子里贴的,即便真的能连上,也不该作为长期使用的线路。同样的道理反过来也成立——你自己的订阅二维码等同账号凭证,截图求助时务必把它遮住,任何人拿到它都能消耗你的流量和设备名额。

扫完之后节点列表会一次涌进几十条,该点哪一个是下一个问题,判断顺序整理在 [几十个节点该点哪一个](/guides/shadowrocket/choose-node/);还没完成购买的话,账号那一关的解法在 [外区 Apple ID 的两条路径](/guides/shadowrocket/overseas-apple-id/)。

## 小结

二维码是容器,不是内容。扫之前先看它的名目和出处,扫之后先看编辑页里是一条网址还是一组服务器参数,这两眼能挡掉绝大多数误导入。相册识别要求图案完整清晰,截图别裁角、别经多次转发。二维码本身不会过期,所谓失效是背后的订阅地址被重置或套餐到期,旧图救不回来。来路不明的节点码不要随手扫,自己的订阅码也不要随手发。
