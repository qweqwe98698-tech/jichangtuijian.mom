装 v2rayN 这一步的失败率比很多人预想的高，但原因几乎都不在软件本身。它是一个绿色压缩包，解压双击就能跑，没有安装向导，也不写注册表。真正卡住人的是三件外围的事：包下错了、目录放错了、被系统的安全机制拦下来却以为软件坏了。

这三件事有个共同特点——出错时给出的反馈都极不友好。下错了包，表现是启动后节点全部连不上；目录放错了，表现是配置改完重启就还原；被拦截时，表现干脆是双击没反应。三种现象看起来都像"软件有问题"，于是不少人开始换版本、换来源，越换越乱，最后装了一个被人重打包过的版本。

所以这一篇只做一件事：把程序稳稳跑起来。判断标准很直白——任务栏托盘出现 v2rayN 图标、右键能弹出菜单，就算过关。至于参数面板里那一堆选项怎么调，属于[首次启动的六项设置](/guides/v2rayn/first-run-setup/)要解决的问题，这里一项都不碰。

## 官方发布页长什么样，怎么一眼认出转载包

v2rayN 的唯一官方分发渠道是 GitHub 上的 2dust/v2rayN 仓库，发布内容集中在仓库的 Releases 页面。这个页面有几个固定特征：每个版本有独立的版本号标签、有发布时间、下方列出若干个可下载的压缩包，并附带哈希校验信息。

对照下面这张表，基本能在几秒内判断手上这个来源是否可信。

| 特征     | 官方发布页                | 常见转载包                           |
| -------- | ------------------------- | ------------------------------------ |
| 分发形式 | 压缩包，解压即用          | 打包成 exe 安装程序，有安装向导      |
| 版本标注 | 明确版本号与发布日期      | 只写最新版、绿色版、纯净版           |
| 文件名   | 含架构与 with-core 等标识 | 加了汉化版、增强版、免配置等字样     |
| 附带内容 | 仅程序与内核              | 附赠所谓免费节点、订阅地址、推广插件 |
| 校验信息 | 提供哈希值                | 无                                   |

最后两行值得多看一眼。凡是"附赠节点"的重打包版本，风险不是内容失效，而是你无法知道它在程序里改了什么。代理客户端处理的是你全部的上网流量，被改过的版本理论上可以做任何事。这一点在[免费节点的安全边界](/free-nodes/safety/)里有更完整的讨论。

> 搜索引擎结果页顶部的广告位、以"官网"自称的中文站点、网盘转存链接，这三类来源都不是官方渠道。v2rayN 没有中文官网。

## 该下哪个包：with-core、无核心版与 64 位/ARM 怎么挑

发布页上通常同时挂着好几个压缩包，命名规则里藏着两个维度：是否自带内核、面向哪种 CPU 架构。

| 包类型          | 是否含内核 | 体积 | 适合谁                           |
| --------------- | ---------- | ---- | -------------------------------- |
| with-core 64 位 | 是         | 较大 | 绝大多数 Windows 用户，首选      |
| 无核心版        | 否         | 很小 | 已有内核、想自行控制内核版本的人 |
| ARM64 版        | 视命名而定 | 中等 | 骁龙等 ARM 架构的 Windows 设备   |

判断逻辑只有两步：先看有没有 with-core，有就选它，因为内核已经放在包里，省掉单独下载和放置的步骤；再看架构，普通台式机和笔记本一律选 64 位，只有明确知道自己用的是 ARM 版 Windows 才选 ARM64。

无核心版之所以存在，是给需要自己指定内核版本的人用的——比如某个协议特性只在特定内核版本里可用。刚上手时不要碰它，缺内核的表现是节点全部超时，而这个现象和网络问题几乎无法区分，白白增加排查难度。

## 解压到哪个目录才不会出权限问题

v2rayN 会把配置文件、订阅信息、日志全部写在自己所在的目录里。这个设计带来一个直接后果：程序目录必须可写。

```text
D:\v2rayN\                 结构示例，非固定路径
├─ v2rayN.exe              主程序
├─ guiConfigs\             配置与订阅数据
└─ bin\                    内核可执行文件
```

以下几个位置都会引发问题，按踩坑频率排序：

1. **Program Files 及其子目录**——系统对该路径有写入保护，程序需要提权才能保存配置，表现为改完设置重启后全部还原。
2. **桌面和下载文件夹**——部分安全软件对这两个位置有额外的行为监控，容易在内核启动时被拦。
3. **含中文或空格的路径**——内核以命令行方式被主程序拉起，路径里的特殊字符在个别版本上会导致参数解析异常。
4. **同步盘目录**——配置文件被频繁读写，同步客户端会不断上传，既慢又可能产生冲突副本。

稳妥做法是在非系统盘建一个纯英文的独立文件夹，比如 `D:\v2rayN`，把压缩包内容整体解压进去。注意是"整体"——有人只把 exe 拖出来，结果内核和配置目录都留在压缩包里，启动后自然什么都不对。

## 被 SmartScreen 和杀毒软件拦截时怎么放行

第一次运行时被拦截是常态，不是异常。代理客户端会修改系统代理设置、创建本地监听端口、拉起子进程，这几个行为组合在启发式引擎眼里非常可疑。

不同的拦截来源，处理方式也不同：

| 现象                            | 拦截方              | 处理方式                               |
| ------------------------------- | ------------------- | -------------------------------------- |
| 蓝色窗口提示"已保护你的电脑"    | Windows SmartScreen | 点更多信息，再点仍要运行               |
| 主程序或 bin 目录下文件突然消失 | 杀毒软件隔离        | 从隔离区恢复，并把整个程序目录加入排除 |
| 启动后立刻被结束，日志无记录    | 安全软件主动防御    | 在防护软件里为该程序添加信任           |
| 提示网络访问请求                | Windows 防火墙      | 允许专用网络访问即可，公用网络可不勾   |

放行的前提是你确信文件来自官方发布页。顺序不能反——不要因为"反正代理软件都报毒"就先关掉防护再下载。正确顺序是：确认来源 → 下载 → 校验 → 再针对性放行这一个目录。

> 把整个安全软件关掉来解决拦截问题，是这一步最常见的过度操作。只需要为程序目录添加排除项，没有必要让整台机器裸奔。

## 缺运行库导致启动即闪退，要补装什么

如果双击后既没有窗口、也没有托盘图标、任务管理器里也找不到进程，几乎可以直接判定为运行时缺失。较新版本的 v2rayN 基于 .NET 构建，需要系统里存在对应版本的桌面运行时（Desktop Runtime，而不是仅 ASP.NET 运行时或 SDK）。

判断和处理按这个顺序：

1. **看进程**——任务管理器里搜进程名，一闪即逝或根本不出现，指向初始化阶段失败。
2. **看事件查看器**——Windows 日志里的应用程序分类下，通常会有一条 .NET 相关的错误记录，能确认缺的是哪一部分。
3. **装桌面运行时**——从微软官方下载页安装与当前版本匹配的 .NET Desktop Runtime，注意选 x64。
4. **重启程序**——不必重启系统，重新双击即可。

另一类闪退是有窗口一闪而过，这通常不是运行时问题，而是配置文件损坏或端口被占用。区分方法很简单：前者连窗口都没有，后者能看到界面闪现。后一类属于连接期故障，处理思路见[能测速却打不开网页的排查流程](/guides/v2rayn/v2rayn-connected-but-no-internet/)。

## 升级到新版本，配置和订阅会不会丢

不会，但前提是升级方式正确。因为配置存放在程序目录内，覆盖式解压是安全的，删除重装才是危险的。

推荐的升级流程：

1. **退出程序**——从托盘右键完全退出，确认内核进程也已结束，否则文件被占用会导致覆盖失败。
2. **备份配置目录**——把存放配置的子目录整体复制一份到别处，几秒钟的事，能省掉重新导入订阅的麻烦。
3. **解压覆盖**——把新版压缩包解压到同一目录，选择覆盖同名文件。
4. **启动验证**——打开程序，确认订阅列表和节点仍在，再检查一次自定义的参数是否保留。

v2rayN 自带的检查更新功能也可以用，但它需要当前网络能访问发布页。首次安装、还没有任何可用节点的阶段，手动下载覆盖更可靠。

## 卸载时哪些残留文件需要手动清理

绿色软件的卸载就是删目录，但有两处例外必须手动处理，否则会留下"卸载了却上不了网"的后遗症。

| 残留项       | 位置                       | 不清理的后果                               |
| ------------ | -------------------------- | ------------------------------------------ |
| 系统代理设置 | Windows 网络设置中的代理项 | 浏览器持续指向已不存在的本地端口，全面断网 |
| 开机自启项   | 启动项列表                 | 每次开机尝试拉起已删除的程序               |
| TUN 虚拟网卡 | 网络适配器列表             | 极少数情况下影响正常网卡的路由优先级       |
| 程序目录     | 解压位置                   | 仅占用磁盘空间                             |

所以正确的卸载顺序是：先在程序里关闭系统代理和开机自启，再退出，最后删目录。顺序反了的话，需要手动进 Windows 的代理设置把开关关掉。这一步不难，但不知道的人往往会以为是网络故障。

## 小结

v2rayN 的安装本身只有解压和双击两个动作，真正需要判断的是来源与环境。来源只认 GitHub 上的 2dust/v2rayN 发布页，包选 with-core 的 64 位版本，解压到非系统盘的纯英文独立目录。首次启动被 SmartScreen 或杀毒软件拦下属于正常现象，按拦截来源针对性放行即可，不需要关闭整套防护。双击完全没反应指向 .NET 桌面运行时缺失，补装后即可解决。托盘出现图标就意味着这一步结束，接下来该处理的是参数面板里那几项决定后续所有行为的默认设置。
