绝大多数人挑机场是从「看别人推荐哪家」开始的，这一步就已经偏了。推荐永远是针对某一类用量给出的，而推荐里往往没写清楚那是哪一类。于是学生党照着重度用户的清单买了 25 元档，重度用户照着学生党的清单买了 50GB，两边都不满意，然后各自得出「这家不行」的结论。

换个起点会顺很多：先把自己的用量写成几个具体数字，再拿这些数字当筛选条件。数字不需要精确，量级对了就够用——月流量是 30GB 量级还是 300GB 量级，对应的是两组完全不重叠的候选；至于是 28GB 还是 35GB，对结果没有任何影响。

这篇给出的是一张映射表：从「你是谁、怎么用」到「买多大档位、要什么线路」。它不负责告诉你买哪一家，只负责把候选范围压缩到你自己能分辨的程度。

## 下单前必须先算清哪四个数字？

四个变量，每个都直接对应一项套餐参数。

| 变量           | 决定什么             | 怎么快速得到                              |
| -------------- | -------------------- | ----------------------------------------- |
| 月流量         | 套餐档位             | 手机设置里的流量统计 + 电脑的日常用量估算 |
| 同时在线设备数 | 是否会触发设备上限   | 数一遍会连的手机、电脑、平板、电视盒子    |
| 主要使用时段   | 对线路等级的要求     | 集中在晚 20:00–23:00 就要往专线靠         |
| 关键服务       | 是否需要特定地区节点 | 列出用不了就等于白买的那两三个服务        |

前两个是「买多大」，后两个是「买什么线」。这四个数字里，最容易被跳过的是第三个。晚间是共享带宽压力最大的窗口，只在白天用和只在晚上用，对同一家机场的体验评价可能完全相反。如果你的使用时间几乎全在晚上，把线路等级的优先级提到流量前面通常更划算。

## 每月到底要用多少流量，怎么在五分钟内估出来？

按最常做的那件事来估，比逐项加总更准，因为流量分布通常极不均匀——一个人 80% 的流量往往集中在一种行为上。

| 主要行为                 | 每小时大致消耗 | 每天 1 小时对应的月流量 |
| ------------------------ | -------------- | ----------------------- |
| 网页浏览、社交、文档协作 | 约 0.1–0.3GB   | 3–9GB                   |
| 音乐流媒体               | 约 0.1GB       | 约 3GB                  |
| 720P 视频                | 约 1GB         | 约 30GB                 |
| 1080P 视频               | 约 3GB         | 约 90GB                 |
| 4K 视频                  | 约 7GB         | 约 210GB                |
| AI 对话与代码补全        | 约 0.05–0.2GB  | 1.5–6GB                 |

> 上表是按常见码率推算的参考值，用来判断量级，不是精确测量结果。实际消耗受平台编码、清晰度自适应、是否走分流规则影响，同一部片子在不同客户端上的流量能差三成以上。

估算方法很简单：找出你每天在代理下花时间最多的那件事，用上表算出月流量，再加三成余量。余量是给两件事留的——一是系统更新、图片加载这类你不会主动注意的后台消耗，二是月底如果流量耗尽，被迫加购的价格通常远高于套餐内单价。

有一类消耗特别容易被漏算：AI 工具本身流量不大，但很多人开着它的同时挂着全局代理，于是所有后台流量都走了机场。如果你的估算结果总是偏低，先去客户端里看一眼是不是全局模式。

## 学生党和轻度用户应该落在哪个档位？

典型画像是：主要用网页、社交、查资料、偶尔看看视频，设备就是一台手机加一台笔记本，使用时段分散在白天和晚上。

这类用户的月流量基本在 30–60GB 区间，买 150GB 的套餐每月会浪费掉七成。更值得关注的反而是两件事：一是价格结构，二是别被年付折算价误导。

| 品牌   | 入门价格   | 月流量 | 计价基准 | 线路     |
| ------ | ---------- | ------ | -------- | -------- |
| 飞猫云 | 7 元/月    | 50GB   | 年付折算 | IEPL     |
| 星岛梦 | 8 元/月    | 60GB   | 年付折算 | 内网专线 |
| 宇宙云 | 14.9 元/月 | 100GB  | 月付     | IEPL     |

> 上表价格与流量为厂商公开资料。飞猫云与星岛梦的入门价是年付折算价，需要一次性支付一整年，不能和月付价直接比较——月付 14.9 元和年付折算 7 元之间的差别，本质上是你愿意承担多少预付风险。

轻度用户还有一个常见误判：认为流量小就可以完全不看线路。实际上流量用得少的人往往对断流更敏感，因为他们的使用场景多是查资料、登录、验证码这类短时高频操作，一次连不上就是一次中断。低价档里能拿到专线的选项值得优先考虑。

## 多设备家庭最容易踩到的限制是什么？

不是流量，是同时在线设备数。

多数机场会限制同一账号的并发设备数，常见上限是 3 到 5 台。一个三口之家实际会连接的设备通常是：三部手机、两台电脑、一台平板、一台电视盒子，合计七台。就算不是同时使用，很多设备的代理客户端是常驻后台的，在服务端看来一直在线。

超限之后的表现很有迷惑性。它一般不会弹出「设备数超限」的提示，而是表现为某一台设备突然连不上、或者刚连上就掉线，用户很容易把它当成节点故障，反复换节点却无济于事。判断方法是：把其他设备的代理全部关掉，只留一台，如果立刻恢复正常，基本可以确认是设备数限制。

家庭场景的另一个变量是电视盒子。它一旦开始播 4K，流量曲线会和其他所有设备完全不在一个量级——一部两小时的 4K 电影可能吃掉 15GB 左右，一周看三部就是 200GB 上下。如果家里有人这么用，档位要按这个人来定，而不是按平均值。

| 家庭规模           | 建议月流量档位   | 需要确认的参数                 |
| ------------------ | ---------------- | ------------------------------ |
| 2 人、无电视盒子   | 100–150GB        | 设备数上限 ≥ 3                 |
| 3–4 人、有电视盒子 | 200GB 以上       | 设备数上限 ≥ 5、是否支持路由器 |
| 合租、账号共用     | 按最重度那个人算 | 是否允许多地区同时登录         |

## 重度流媒体和下载用户要额外盯住哪一项？

倍率。

有些套餐标称的流量是「基础流量」，实际扣除时会按节点倍率换算。走高倍率节点时，1GB 的实际下载可能扣掉 2GB 甚至更多额度。对每月只用 30GB 的人来说，倍率的影响可以忽略；对每月 300GB 的人来说，倍率是决定性变量，它能让一个看起来 20 元 150GB 的套餐实际只值 75GB。

购买前要在套餐页面找到倍率说明，确认三件事：默认节点是几倍、哪些地区是高倍率、是否有 1 倍率的常规节点可用。如果页面上完全找不到倍率信息，不代表没有，只代表没写清楚，这一点应该在试用时验证。

大流量用户可以关注的公开规格：

| 品牌     | 入门价格 | 月流量 | 计价基准 | 折合每 GB  |
| -------- | -------- | ------ | -------- | ---------- |
| 灵猫网络 | 19 元/月 | 150GB  | 月付     | 约 0.13 元 |
| 一翻云   | 20 元/月 | 150GB  | 月付     | 约 0.13 元 |
| 速界     | 25 元/月 | 150GB  | 月付     | 约 0.17 元 |

> 每 GB 单价由公开的入门套餐价格除以流量得出，任何人都能复算。它反映的是标称流量的价格效率，不包含倍率折算，也不代表实际速度或稳定性——后者需要你自己在试用期验证。

## 跨境办公和远程协作对线路的要求差在哪里？

差在对「持续连接」的要求上。

看视频是单向大流量，偶尔卡顿几秒可以靠缓冲吃掉；视频会议、远程桌面、SSH 会话是双向低延迟，一次 300 毫秒的抖动就是一次明显的卡顿，一次断流就是一次掉线重连。这类用户真正需要的不是带宽峰值，是延迟的稳定性。

对应到选购上有三个具体要求：一是线路要往 IEPL、IPLC 这类企业专线靠——它们不经过公共网络出口，晚高峰的表现波动更小；二是要确认长连接不会被主动断开，有些线路会对超过一定时长的空闲连接做回收；三是节点地区要和你的协作对象或服务器所在地匹配，绕远路的延迟是加不回来的。关于各类线路的技术差别，[协议知识栏目](/protocols/)有专门的说明。

办公场景还有一条纪律性的建议：不要把工作依赖压在单一机场上。这不是稳定性问题，是可用性问题——任何服务都会有维护窗口和突发故障，而你的会议不会因此推迟。

## 人在海外，选择逻辑要反过来吗？

要，而且反得很彻底。

国内用户买机场是为了出境访问；海外用户的需求通常是回连国内——看国内的视频平台、用国内的音乐服务、访问只对国内 IP 开放的银行或政务系统。这两个方向用的是完全不同的线路和 IP 资源，一个标准的出境套餐并不自动包含回国节点。

购买前必须确认的是：服务商是否明确提供回国方向的节点、这些节点是否包含在你要买的档位里、是否需要额外付费。这一点在套餐介绍页上经常写得很含糊，最好在试用期直接测。测法也简单：连上回国节点，打开一个只对国内开放的服务看能否正常播放。

## 把档位翻译成筛选条件，具体怎么用？

现在你手上应该有四个数字了。把它们写成一行筛选条件，形如：

```text
月流量 ≥ 100GB
设备数上限 ≥ 3
线路类型 = IEPL / IPLC / 内网专线
必须可用：视频平台 A、AI 工具 B
月预算 ≤ 20 元（先按月付算）
```

带着这行条件去看任何一份榜单或评测，操作方式是「先删后比」：把不满足硬条件的直接划掉，剩下的再排序。这个动作通常能把十几家压到三四家，而这三四家之间的差别，靠读资料是分不出来的，只能动手测。

## 小结

需求先于品牌，这是选机场唯一不会出错的顺序。月流量决定档位，设备数决定会不会莫名其妙掉线，使用时段决定要不要为专线多付钱，关键服务决定哪些候选可以直接排除。轻度用户的钱应该花在线路而不是流量上，家庭用户要先数清设备，重度用户必须搞清倍率，海外用户要确认回国节点是否包含在套餐内。把这四个数字写成一行筛选条件，剩下的工作就只是核对规格和动手验证。
