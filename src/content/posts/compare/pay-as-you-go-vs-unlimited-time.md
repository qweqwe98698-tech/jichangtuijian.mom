两种套餐摆在一起时，宣传语几乎一样：都在说「不浪费」「用多少算多少」「不用每月续」。但它们承诺的东西根本不是一回事。按量计费卖给你的是一个**单价**——每 GB 多少钱，这个数字在你付款的那一刻就已经兑现完毕了。不限时流量包卖给你的是一段**服务寿命**——「这些流量什么时候用完都行」，而这句话成立的前提是服务方在那之前一直开着。

差别就在这里：前者的履约在付款时就结束了，后者的履约要延续到你把最后一 GB 用完为止。所以两者不是「哪个更划算」的关系，而是「你愿意把不确定性放在哪一端」的关系。一个把风险留在自己手上（可能买贵了），一个把风险交给对方（可能拿不到）。

这篇只比较计量方式这一个维度。付费周期长短是另一回事（月付还是年付有[专门一篇](/compare/how-to-choose-airport/monthly-vs-yearly/)），单位价格的换算也是另一回事（[每 GB 实际单价怎么算](/compare/how-to-choose-airport/value-calculation/)那篇给了公式）。这里假设你已经会算单价，只剩下「按什么方式计量」这个问题。

## 两种计费逻辑，差在哪几个字段上

把两者拆成字段来看，分歧其实非常清楚。

| 对比项     | 按量计费                   | 不限时流量包                         |
| ---------- | -------------------------- | ------------------------------------ |
| 计费单位   | 流量（有的按时长）         | 流量总额，一次性买断                 |
| 到期方式   | 通常无月度周期，用完为止   | 名义上无到期日                       |
| 未用完部分 | 留在账户里                 | 留在账户里                           |
| 单价确定性 | 购买时确定，之后不变       | 购买时确定，但摊薄取决于能用多久     |
| 履约周期   | 极短，付款即完成交付       | 极长，要延续到最后一 GB              |
| 失效条件   | 流量耗尽                   | 流量耗尽、或服务终止、或触发闲置条款 |
| 典型用途   | 波动用量、备用位、短期需求 | 低频长期需求、囤积心态               |
| 价格观感   | 单价偏高                   | 折算下来单价很低                     |

第五行是全表的重点。**履约周期的长短，决定了这笔交易的风险结构。** 按量计费的交付在付款后几分钟内就完成了，之后你手里的流量是一份已经到手的资产；不限时流量包则要求服务方在未来一段无法预估的时间里持续存在，你手里的是一张欠条。

顺带说一句常见的混淆：有些套餐叫「不限时」，但其实指的是「有效期一年」或「有效期至用完为止，最长两年」。这类严格说是长有效期的流量包，风险等级明显低于真正无期限的版本。看清楚这一行字，比看总价重要得多。

## 两种套餐分别把风险转移给了谁

同一笔交易里，双方各自承担哪一部分不确定性，可以直接列出来。

| 不确定性来源       | 按量计费由谁承担           | 不限时流量包由谁承担 |
| ------------------ | -------------------------- | -------------------- |
| 你用不完，钱花多了 | 你（但可少量分次购买）     | 你                   |
| 你用超了，需要再买 | 你（随时可补）             | 你                   |
| 服务方停止运营     | 几乎不涉及（余量本来就少） | 你，且全额           |
| 线路质量下降       | 你，但可以随时不再买       | 你，且已经付过钱了   |
| 价格上涨           | 你，下次购买时体现         | 服务方（已锁价）     |
| 现金流压力         | 服务方                     | 你                   |

倒数第二行是不限时套餐唯一真正的优势：锁定价格。但要拿到这个优势，你得先承担上面那两行——服务终止和质量下降的成本都落在你这边，而且是在已经付完款的状态下。

这个结构和年付其实是同一类问题，只是走得更远。年付押的是十二个月，不限时押的是「一直」。[年付折扣与预付风险的换算方式](/risk/annual-plan-risk/)那篇给出的估算思路在这里同样适用：**把预付金额除以你估计的剩余可用月数，得到一个每月实际成本，再和包月价格比较。** 如果你估计这家还能稳定开一年，那么一份标价相当于十个月包月费的不限时套餐才刚刚划算；估计只能开半年，它就是亏的。

## 什么样的用量特征适合按量计费

按量的优势区间很具体，看两个变量就能定：月均用量，以及需求是否连续。

| 用量特征         | 需求连续性         | 更合适的方式         |
| ---------------- | ------------------ | -------------------- |
| 每月不足 10 GB   | 断续，一周用几次   | 按量计费             |
| 每月 10–20 GB    | 断续，有明显空档月 | 按量计费             |
| 每月 10–20 GB    | 每天都用           | 低档包月             |
| 每月 20–100 GB   | 稳定               | 包月，按单价择优     |
| 每月 100 GB 以上 | 稳定               | 包月大流量档         |
| 几乎不用，只备用 | 数月一次           | 按量计费（作备用位） |

要估自己的月用量，可以用码率倒推。下表是**按常见码率推算的参考值，不是实测数据**，实际消耗随编码方式、清晰度、平台策略差异很大：

| 使用场景           | 常见码率参考 | 每小时约消耗       |
| ------------------ | ------------ | ------------------ |
| 网页浏览、文档协作 | —            | 0.1–0.3 GB         |
| 音乐流媒体         | 约 0.3 Mbps  | 约 0.13 GB         |
| 视频会议           | 约 2 Mbps    | 约 0.9 GB          |
| 1080p 视频         | 约 5 Mbps    | 约 2.2 GB          |
| 4K 视频            | 约 15 Mbps   | 约 6.6 GB          |
| 文本类 AI 对话     | —            | 每小时几十 MB 量级 |

> 换算口径：1 Mbps 持续一小时约等于 0.45 GB。表中数字用于估算量级，不同平台的自适应码率会让实际结果上下浮动，一半以上的偏差都属于正常。

按这张表推一下就会发现，看一部 1080p 电影大约两三 GB，而纯文本工作一整天可能都用不到 1 GB。**用量结构决定套餐结构**：如果你的流量几乎全是视频，按量计费会很快显得贵；如果主要是文本、代码和网页，按量能撑很久。

## 「不限时」通常受哪些条款限制

字面上的无期限，实际上被一组条款圈起来了。常见的有这么几类，购买前应当逐条在服务条款或套餐说明里找一遍：

1. **闲置判定。** 一段时间（常见的说法是连续数月）不登录或不产生流量，账户可能被标记为闲置，流量随之作废。这一条对「买来放着备用」的用法是致命的。
2. **单日或单月上限。** 名义上流量不限时间，但每天最多用多少有另一条限制。对偶尔需要集中下载的场景影响很大。
3. **节点范围差异。** 不限时套餐可用的节点组，未必等同于包月套餐。专线、高倍率节点常常被排除在外，这一点在宣传页上通常不写。
4. **倍率不同。** 同样扣 1 GB，走高倍率节点实际可能扣掉数倍。这会让「不限时」的实际总量大幅缩水，具体的折算方法在[每 GB 实际单价怎么算](/compare/how-to-choose-airport/value-calculation/)里有完整公式。
5. **转让与退款。** 绝大多数不接受转让，也不接受按剩余量退款。
6. **调整权。** 条款里通常保留「有权调整套餐内容与服务范围」的表述，这意味着「不限时」并不构成对未来的硬承诺。

> 这些条款单独看都不算不合理，服务方需要它们来控制成本。问题在于它们通常写在很后面，而宣传位上只有「一次购买，永久使用」八个字。审条款的时间成本是十分钟，看不看的差别可能是全部预付款。

## 服务方停运之后，永久套餐还剩什么

答案很直接：**什么都不剩。** 流量余额是对方账本上的一个数字，不是你持有的资产，服务停止的那一刻它归零，不存在任何残值、任何优先受偿、任何可转让的形态。

这一点和年付还不完全一样。年付至少有一个明确的到期日，你能算出自己的最大损失，也知道敞口每个月都在缩小。不限时套餐没有这条衰减曲线——它的敞口取决于你用得多快，如果你买它的初衷就是「慢慢用」，那么敞口会在很长一段时间里维持在高位。

所以有一条经验规则值得记：**不限时套餐的合理购买额，应当控制在你能坦然接受完全损失的范围内。** 如果一份套餐的价格让你在想到「万一它明天关了」时会觉得肉疼，那就说明买多了。这类服务方的连续性无法从外部验证，能做的只有观察运营信号，[跑路前的早期信号与判断阈值](/risk/exit-scam-signs/)那篇整理了具体的观察项和阈值。

## 用按量套餐当备用线路，要注意什么

这是按量计费最贴合的用途。备用位的需求特征——平时几乎不消耗、只在主力异常时顶上几天——正好落在按量最划算的区间，具体的搭配与成本核算见[主备双线怎么配](/compare/how-to-choose-airport/single-vs-backup-airport/)。这里只补充几个容易翻车的细节：

1. **别买得太少。** 备用位真正被启用时，往往就是主力彻底不能用的几天，用量会集中爆发。按你日常一周的用量准备，而不是按「反正用不上」准备。
2. **先确认没有闲置条款。** 上一节第一条正是为这个场景准备的坑：放了三个月没用，需要的那天发现已经作废。
3. **备用位要和主力错开。** 换一家但用同一批上游线路，等于没有备份。运营方、线路类型、入口位置这三项至少错开两项。
4. **每月验证一次。** 验证的标准不是「能连上」，而是「能完成一次真实使用」——连上之后把常用的东西跑几分钟。没验证过的备份不算备份。
5. **提前配好，不要临时配。** 配置留在客户端里、随时可切，才有意义；地址存在一个已经打不开的面板里就没有意义了。

## 购买不限时套餐前，必须确认的四项

如果读完还是想买，把下面四项在下单页和服务条款里逐条找到答案，找不到就当作否定答案处理。

| 必须确认项     | 具体要找到什么                           | 找不到时的默认处理             |
| -------------- | ---------------------------------------- | ------------------------------ |
| 闲置条款       | 连续多久不使用会失效                     | 按「会失效」处理，定期登录     |
| 用量上限       | 是否有单日或单月封顶                     | 按「有封顶」处理               |
| 节点范围与倍率 | 可用节点组，以及各组倍率                 | 按「不含专线、倍率不低」处理   |
| 运营连续性证据 | 运营起始时间、公告更新频率、工单响应记录 | 按「无法验证」处理，压低购买额 |

第四项没有标准答案，只有可查的迹象。公开的运营起始时间、公告的更新密度、工单的历史响应速度，这三样在下单前十分钟就能看完，比任何宣传语都有信息量。想看逐家的核对结果，可以从[各家的完整评测](/reviews/)入手；只想快速比单价的话，[按每 GB 单价排序的性价比榜](/rankings/value/)是更省时的入口。

## 小结

按量计费和不限时流量包的区别不在价格，在履约周期：一个付完款交易就结束了，一个要求对方在未来很长一段时间里持续存在。按量适合用量波动、需求不连续以及备用位这三类场景，代价是单价偏高；不限时看起来单价极低，但那个低单价要靠「能一直用下去」来兑现，而这件事没有任何用户侧的验证手段。真要买，先把闲置条款、用量上限、节点范围与倍率这三项找清楚，再把金额压到你能坦然接受全损的水平。长期主力线路，仍然建议用月付或季付。
