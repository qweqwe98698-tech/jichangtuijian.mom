选购经验会过期，但过期的方式很隐蔽：它不会报错，只是悄悄地把你引向一个已经不存在的最优解。一篇 2024 年写得很扎实的推荐文，今天读起来依然逻辑通顺、条理清楚，问题在于它比较的那些套餐、那些线路、那些协议名单，有一部分已经不在市场上了。

所以这篇的比较对象不是"哪家更好"，而是**两个时间点的判断标准本身**。同行的文章几乎都在做横向比较——同一时刻的不同维度；这篇做的是纵向比较——同一维度在不同时刻的取值。读完你应该能做两件事：把手头那些旧结论里该淘汰的挑出来，以及判断一篇没标日期的文章值不值得往下读。

需要先声明口径：下文涉及市场变化的描述来自本站对公开资料与厂商页面的持续跟踪，属于趋势观察，不是抽样统计；涉及具体规格的部分都来自各家公开资料。凡是需要动手才能确认的能力，一律按厂商声明处理。

## 两年前的哪些挑选经验现在已经失效？

先把失效的部分单独列出来，方便你对照手上的旧笔记：

| 旧经验                             | 当时为什么成立               | 现在的状况                                                   |
| ---------------------------------- | ---------------------------- | ------------------------------------------------------------ |
| "看到某几种老协议就说明这家跟不上" | 那时协议代际差距确实拉得很开 | 协议名单已经普遍收敛，靠协议名判断服务商水平的信噪比大幅下降 |
| "专线是高端机场的标志"             | 专线线路成本高、供给少       | 专线标注已下沉到中档套餐，标注本身不再构成区分度             |
| "节点数量越多越好"                 | 节点多曾经意味着资源投入大   | 节点数可以靠拆分和复用做大，与可用性关系微弱                 |
| "测速跑满就是好线路"               | 峰值带宽曾是最稀缺的资源     | 长连接稳定性成为更常见的瓶颈，峰值反而容易达标               |
| "一份年度榜单能用一年"             | 市场变化慢，套餐半年不动     | 套餐结构与线路调整节奏明显加快，年度榜单需要季度维护         |
| "免费试用够长，可以慢慢测"         | 试用政策普遍宽松             | 试用窗口普遍收紧，验证必须按优先级压缩到半小时内完成         |

这六条里，前四条是"标准变了"，后两条是"节奏变了"。下面四节分别展开变化最大的四个方向。

## 协议主流的更替对普通用户意味着什么？

变化的实质不是"出现了更快的协议"，而是**协议之间的差异正在从性能维度转向抗封锁维度**。早期各代协议之间在握手方式和加密开销上差距明显，选错会有肉眼可见的体感差异；现在主流方案的性能已经接近，真正拉开差距的是在特定网络环境下能不能建立连接、连上之后能不能维持住。

一个可以核对的公开事实：本站收录的 16 家机场，公开资料里全部把 VLESS 列入支持协议，另有部分同时提供 Trojan、Shadowsocks、VMess 与 Hysteria2。也就是说，协议清单在这一批服务商之间已经高度趋同，它不再是一个有区分度的筛选条件。

对普通用户来说，这带来三个实际改变：

- **不用再追"最快的协议"**。在同一条线路、同一台落地服务器上，协议之间的速度差远小于线路差异，这一点在[协议与线路的选择专题](/protocols/how-to-choose/)里有完整的归因拆解。
- **要开始关心客户端版本**。新的伪装方式对客户端有最低版本要求，旧版本连不上时报的错往往和协议本身无关，容易误判成机场的问题。
- **要看协议组合而不是单个协议**。同时提供 TCP 系与 UDP 系方案的服务商，在网络环境变化时的可用性更好，因为两类方案的失效原因不同。

> 提醒一句：协议名称在节点名里的标注方式各家不统一，同一个词在不同机场可能指向不同的传输层配置。以后台的订阅类型说明为准，不要以节点名里的字母缩写为准。

## 专线价格结构发生了什么变化？

两年前，"IEPL"这类标注基本只出现在高价套餐里，看到它就意味着这是一家定位偏上的服务商。现在情况不同了：本站收录的 16 家中，多数在公开资料里把线路标注为 IEPL 类专线，另有少数标为内网专线或中转与直连组合。当一个标签接近全覆盖，它就不再承载区分信息。

真正的变化发生在**价格与倍率的组合方式**上。专线出现在中档甚至入门套餐里，代价通常转移到了三个地方：

| 转移位置 | 具体表现                               | 你该怎么核对                                 |
| -------- | -------------------------------------- | -------------------------------------------- |
| 流量倍率 | 专线节点的倍率高于普通节点             | 在后台的节点列表里逐条看倍率，不要只看套餐页 |
| 节点比例 | 套餐里只有少数几条是真专线，其余是中转 | 数一下标注专线的节点占全部节点的比例         |
| 限速阈值 | 专线节点单独设置更低的速率上限         | 连续下载数分钟，观察速率是否在某个点被压住   |

结论是：**看到专线标注不要加分，把倍率折进单价再比较**。同样标称 100GB 的两个套餐，一个全程 1x，一个专线段 2x 且你八成流量走专线，实际可用量相差近一倍。完整的折算方法在[把套餐折成每 GB 实际单价](/compare/how-to-choose-airport/value-calculation/)那篇里，这套算法本身没有过期，只是现在必须多算倍率这一步。

## AI 工具为什么把长连接稳定性推成硬指标？

这是四项变化里对使用体验影响最大的一项。传统的网页浏览和视频播放对短暂断流有很强的容忍度：网页重新加载一次，视频缓冲两秒，用户几乎无感。AI 工具不一样。

长时间的对话、流式输出的响应、需要持续会话的接口调用，都建立在一条**必须活着的连接**上。这条连接断开时，损失不是"慢了两秒"，而是整段输出中断、上下文丢失、任务需要从头再来。同样一条线路，用来刷视频完全够用，用来跑长会话就可能每隔十几分钟出一次问题。

这直接改变了该测什么：

| 使用场景            | 关键指标                       | 峰值带宽的作用 |
| ------------------- | ------------------------------ | -------------- |
| 网页浏览            | 首字节延迟                     | 中等           |
| 视频播放            | 持续带宽下限                   | 高             |
| 文件下载            | 峰值带宽                       | 最高           |
| AI 长会话与流式输出 | 连接存活时长、出口 IP 是否漂移 | 很低           |
| 视频会议与远程桌面  | 抖动、丢包率                   | 低             |

注意最后两行：对这两类用途来说，测速软件跑出的漂亮数字几乎不提供任何信息。要测的是连续挂上一两个小时会不会掉、掉了之后多久恢复、以及出口 IP 在会话中途会不会变。前两项的记录方法在[稳定性怎么自己复测](/compare/how-to-choose-airport/stability-metrics/)里；出口 IP 漂移会带来的连锁反应，在[区域限制与解锁专题](/unlock/region-lock/)里有单独讨论。

## 榜单的有效期为什么缩短了？

因为排名结论依赖的前提在更快地变化。一份榜单实际上是"在某组套餐、某批线路、某个封锁环境下按某套权重排出的顺序"，这四个前提里任何一个变了，顺序都可能重排。

过去这四项一年动一到两次，现在的节奏明显更密。套餐结构会随促销周期调整，线路会随上游合同和封锁事件更换，协议部署会随客户端版本推进，而封锁事件本身没有规律可言。结果是：半年前的第一名今天可能仍然不错，但把它作为第一名的那些理由，已经有一半需要重新验证。

实践中的处理方式是把内容按"保质期"分层：

| 内容类型                         | 大致保质期 | 过期后的处理                     |
| -------------------------------- | ---------- | -------------------------------- |
| 方法论（怎么估流量、怎么折单价） | 数年       | 基本不动，可直接沿用             |
| 判断标准（该看哪些指标）         | 一年左右   | 每年复核一次，增删指标           |
| 具体名单与排序                   | 一个季度   | 到期必须重排，不重排就下架       |
| 价格与套餐规格                   | 随时可能变 | 以官网当前页面为准，文章只作参考 |

这也是为什么本站的榜单页与品牌页把厂商公开资料、实测状态和编辑判断分层存放：规格变了只需要更新一层，方法论那一层不受影响。

## 哪三项判断标准至今没有变？

变化讲完了，更值得记住的是没变的部分。这三项从这个市场存在的第一天起就是第一梯队的判断依据，未来大概率也不会变：

1. **晚高峰的实际表现**。工作日 20:00 到 23:00 是共享带宽压力最大的窗口，任何机场的真实水平都在这个时段暴露。白天测得再好，也只说明它白天好。
2. **每 GB 的实际单价**。把标称流量按倍率折成可用流量，再除进月费，这是唯一能让不同套餐进入同一个坐标系的方法。省钱的位置会变，算法不会变。
3. **售后响应速度**。发一条工单多久有人回，这一项在平时毫无存在感，在故障和封锁期间决定了你是等两小时还是等两天。它也是最难伪造的指标，因为你自己发一条就知道了。

第三项还有一个衍生用途：它能帮你识别那些低价但几乎没有售后投入的套餐，这部分的成本结构在[便宜机场省在哪五个地方](/compare/how-to-choose-airport/cheap-airport-truth/)里拆得很细。

## 看到一篇没标日期的机场推荐，该怎么处理？

没有日期不等于没有价值，但需要你自己给它定一个时间戳。按下面的顺序判断，一两分钟就够：

1. **看协议清单**。如果通篇没有提到当下常见的协议组合，或者把某个早已普及的方案当成稀有卖点，这篇大概率写于两年前以上。
2. **抽查一个价格**。随便挑一个文中提到的套餐去对应官网核对价格和流量，对不上就说明规格部分已经失效。
3. **看专线是怎么被描述的**。仍然把专线当成高端独占标志的，时间戳基本可以定在标注普及之前。
4. **看有没有提到长连接或 AI 场景**。完全不涉及这类需求的文章，通常写在这个需求成为主流之前。
5. **决定读法**。方法论部分照读，名单和排序部分全部作废，价格一律以官网为准。

这一整套检查其实是[六个可以自己核验的可信度信号](/compare/how-to-choose-airport/review-credibility-check/)里"更新时间与内容是否一致"那一条的展开版本。没有日期的文章不是最危险的，标着最近日期却引用着两年前规格的才是。

## 小结

变了的是四件事：协议清单趋同，判断权重从性能转向抗封锁；专线标注下沉到中档，区分度转移到倍率与节点比例；AI 类长会话把连接存活时长推成硬指标，峰值带宽退居次位；榜单的有效期从半年压到一个季度。没变的也是三件事：晚高峰表现、每 GB 实际单价、售后响应速度。处理旧内容的原则很简单——方法论继承，名单作废，价格以官网为准。带着这份更新过的标准，再去看任何一份年度榜单，你会更清楚它在比什么，以及它有没有比你关心的那些东西。
