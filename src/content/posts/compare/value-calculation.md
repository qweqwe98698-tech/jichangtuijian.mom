「性价比高」是机场推荐里出现最多、含义最空的一句评价。它之所以空，是因为分子分母都没定义：价格是月付价还是年付折算价？流量是标称值还是你真正能用掉的量？两个人对着同一份套餐，一个觉得超值一个觉得被坑，多半不是判断力的差别，而是他们各自默认的分母根本不是同一个东西。

这篇文章要做的事很窄：给出一个能算出具体数字的流程，把任意一份套餐折成「每 GB 实际单价」。有了这个数字，价格第一次变得可以横向比较——你可以拿它去比同价位的另一家，也可以拿它去比自己现在正在用的那份。全文的产出物就是一个带单位的数，不涉及推荐任何品牌。

先说清口径：本站收录的 16 家均为推广合作关系。下文引用的价格与流量区间来自品牌公开资料，入门档标价大致在 7 元到 25 元、标称流量 50GB 到 150GB 之间。这里刻意不写「月费 7 元」——标价最低的三家标注的计价基准是**年付折算价**,月付并拿不到这个数。计价基准不一致时先统一，否则后面所有计算都不成立。

## 为什么直接比月费几乎一定会选错

因为月费这个数字里同时藏着四个变量，而它们的取值范围都不小。

| 藏在月费里的变量 | 常见取值跨度        | 对实际价值的影响   |
| ---------------- | ------------------- | ------------------ |
| 计价基准         | 月付价 / 年付折算价 | 同一家可差三到四成 |
| 标称流量         | 50GB–150GB          | 三倍               |
| 常用节点倍率     | 0.5×–5×             | 十倍               |
| 设备数上限       | 2–10 台             | 决定能否一份多用   |

四个变量叠加，两份月费都是 20 元的套餐，实际价值差出五倍以上完全可能。把它们压缩成一个可比的数，需要按固定顺序拆开——这也是这篇和[低价机场省在哪里](/compare/how-to-choose-airport/cheap-airport-truth/)那篇的分工：那篇解释价格为什么能这么低，这篇只负责换算。

## 标称流量和实际可用流量差在哪里

标称流量是按 1× 倍率计的名义额度，实际可用流量是你按自己的节点使用习惯扣完之后剩下的量。差距来自三处：

- **倍率折损**，主要来源，下一节展开。
- **有效期截断**：多数套餐流量按月清零，用不完不结转。如果你的用量集中在月初，月末剩下的额度等于白付。
- **重置口径**：有的按自然月重置，有的按购买日起算 30 天，跨月使用时会出现「以为还有额度、实际已清零」。

> 口径提示：本文所有数字都以「一个计费周期内」为单位。如果套餐的流量周期不是一个月（比如 30 天或不限时），要先折算到月，否则单价没有可比性。

## 常见倍率档位怎么折算，折算表怎么用

倍率的关键不在于表本身，而在于**你不会只用一种倍率的节点**。真正需要算的是加权平均倍率：按你在各类节点上花掉的流量占比加权。

先估自己的使用分布，再填这张表：

| 节点类型              | 常见倍率 | 你的使用占比 | 加权项（倍率 × 占比） |
| --------------------- | -------- | ------------ | --------------------- |
| 冷门地区 / 低负载中转 | 0.5×     | 10%          | 0.05                  |
| 普通中转、直连        | 1×       | 50%          | 0.50                  |
| 优质中转 / 解锁节点   | 2×       | 30%          | 0.60                  |
| 专线入门档            | 3×       | 10%          | 0.30                  |
| 高等级专线            | 5×       | 0%           | 0.00                  |
| **合计**              | —        | 100%         | **1.45**              |

上例的加权平均倍率是 1.45。也就是说，标称 100GB 的套餐，对这个使用习惯的人来说实际可用量是 100 ÷ 1.45 ≈ 69GB。

估占比不需要精确。多数人的分布其实很极端：要么几乎全在 1× 的普通节点上（加权倍率接近 1），要么因为要看流媒体、用 AI 工具而长期挂在 2×–3× 的解锁节点上（加权倍率 2 以上）。落在哪一类，你自己心里有数。倍率高低本身不是缺点，专线的采购成本本来就高，这一点在[专线的真实定义](/protocols/how-to-choose/iepl-iplc-explained/)里有说明。

## 每 GB 实际单价的完整计算步骤

四步，用计算器就能做完。

1. **统一计价基准**。把年付、季付价格换算成月均价：年付总价 ÷ 12。如果只想比月付，就统一取各家的月付价，不要混用。
2. **算加权平均倍率**。按上一节的表，用你的实际使用分布加权求和。
3. **求实际可用流量**：标称流量 ÷ 加权平均倍率。
4. **求每 GB 实际单价**：月均价 ÷ 实际可用流量。

写成一行：

```text
每 GB 实际单价 = 月均价 ÷ (标称流量 ÷ 加权平均倍率)
              = 月均价 × 加权平均倍率 ÷ 标称流量
```

用两份结构示例的套餐走一遍（数值为演示用，非任何具体品牌）：

| 项目               | 套餐甲      | 套餐乙      |
| ------------------ | ----------- | ----------- |
| 标价               | 15 元/月    | 96 元/年    |
| 计价基准           | 月付        | 年付        |
| 统一后月均价       | 15 元       | 8 元        |
| 标称流量           | 100GB       | 100GB       |
| 你的加权平均倍率   | 1.2         | 2.8         |
| 实际可用流量       | 83GB        | 36GB        |
| **每 GB 实际单价** | **0.18 元** | **0.22 元** |

标价上乙便宜近一半，折算后反而更贵。差别全在倍率那一行——乙的低价档只在高倍率节点上开放优质线路，而这位用户恰好主要用那些节点。换一个只用普通中转的人来算，乙会赢得很轻松。**同一份套餐对不同人有不同单价，这不是算法的缺陷，是它的全部意义。**

## 设备数上限和限速阈值该怎么做修正

上一节的数字还需要两次修正，都用乘一个系数的方式处理，不必追求精确。

**设备数修正。** 如果套餐允许的同时在线设备数低于你的需求，你要么多买一份，要么频繁手动切换。做法是：所需设备数 ÷ 套餐允许设备数，向上取整，得到「实际需要买几份」，把单价乘以这个倍数。需要 5 台但套餐只允许 3 台，单价直接翻倍。

**限速修正。** 限速不减少流量，但降低这些流量的可用价值。建议按体感分三档：

| 限速情况                 | 修正系数 | 说明                           |
| ------------------------ | -------- | ------------------------------ |
| 无明显速率约束           | ×1.0     | 单线程能跑满，多设备不互相压制 |
| 单线程限速但多线程可跑满 | ×1.15    | 日常浏览无感，下载受影响       |
| 节点级带宽封顶或用量降速 | ×1.4     | 晚高峰和多设备场景明显受损     |

修正系数是主观经验值，不是实测结论，作用是防止你把一份「便宜但用起来处处受限」的套餐算成最优解。怎么触发测试确认属于哪一档，[低价机场那篇](/compare/how-to-choose-airport/cheap-airport-truth/)给了具体做法。

## 免费流量、赠送流量和活动流量要不要计入

原则是：**只计入确定会到账、且在有效期内你确实用得掉的部分。**

| 流量类型        | 是否计入       | 理由                               |
| --------------- | -------------- | ---------------------------------- |
| 套餐固定流量    | 计入           | 每周期确定发放                     |
| 签到 / 打卡赠送 | 打折计入       | 需持续操作，按你实际会坚持的天数估 |
| 首充一次性赠送  | 按 12 个月摊薄 | 只发一次，摊到年比摊到月更接近真实 |
| 限时活动流量    | 不计入         | 无法确认下个周期还有               |
| 邀请奖励        | 不计入         | 取决于外部因素，不可控             |

把一次性赠送直接加进当月分母，是最常见的一种自欺。500GB 首充赠送摊到十二个月是每月约 42GB，摊到第一个月则会让首月单价看起来低得不真实，然后第二个月开始你会觉得「怎么突然变贵了」。

## 算完之后，多少单价区间算合理

按品牌公开资料的入门档做一次不含倍率修正的粗算：标价 7 元到 25 元（低端三家为年付折算价，非月付）、标称 50GB 到 150GB，得到的名义单价大致在每 GB 0.12 元到 0.20 元之间。这是分母最宽松情况下的下限。

做完倍率加权之后，参考区间大致是这样：

| 使用画像                 | 加权倍率参考 | 每 GB 实际单价参考区间 |
| ------------------------ | ------------ | ---------------------- |
| 只用普通中转，轻度浏览   | 1.0–1.3      | 0.12–0.25 元           |
| 混合使用，含部分解锁节点 | 1.5–2.0      | 0.20–0.40 元           |
| 长期使用专线节点         | 2.5–4.0      | 0.40–0.80 元           |

> 这些区间是按公开规格推算的参考值，不是实测结论。它们的用途是判断「自己算出来的数字有没有离谱」，不是用来给某家机场打分。算出 0.6 元并不意味着买贵了——如果你确实一直在用专线节点，这就是专线的价格。

单价算完之后不要直接下单。正确顺序是先用[可复测的稳定性指标](/compare/how-to-choose-airport/stability-metrics/)筛掉晚高峰不能用的，再在合格的候选里比单价。单价最低的那家如果每天晚上断流，它的实际单价是无穷大。

## 同一份算法怎么用来判断年付是否真的更划算

把年付看成「用折扣换承诺」，就能用同一个公式算出这个折扣值多少钱。

1. 先分别算出月付和年付两种基准下的每 GB 实际单价。
2. 求差额：（月付单价 − 年付单价）× 你的年度实际可用流量，得到一年能省下的绝对金额。
3. 把这个金额和年付总价对比。省 90 元、预付 240 元，意味着你为了 90 元把 240 元押了十二个月。
4. 再问一句：如果这家机场在第五个月停止服务，剩余七个月的预付款你能接受损失吗？

关键在于第三步给出的是绝对值而不是百分比。「年付省 35%」听起来很多，换算成绝对金额往往只有几十块——这个数字和你要承担的预付风险放在一起看时，结论常常会反过来。完整的取舍框架在[用风险敞口决定月付还是年付](/compare/how-to-choose-airport/monthly-vs-yearly/)里，另一种计量方式的比较则在[按量计费与不限时套餐的取舍](/compare/how-to-choose-airport/pay-as-you-go-vs-unlimited-time/)。

## 小结

性价比是一个可以算出来的数，不是一种感觉。流程只有四步：统一计价基准、算加权平均倍率、求实际可用流量、除出每 GB 单价，再用设备数和限速做两次修正。这套算法最有价值的地方在于它把「同一份套餐对不同人价值不同」这件事显性化了——你的倍率分布决定了你的单价，别人的结论不能直接搬过来用。算完之后记得把顺序摆对：先筛稳定性，再比单价。想省掉重复计算，可以直接看[按同一算法排过序的性价比榜](/rankings/value/)。
