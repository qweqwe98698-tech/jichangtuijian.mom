前面几篇分别拆过 IP 属性、出口漂移、长连接中断这些单点问题。每一篇都能解决一个具体症状，但读完之后往往还剩一个问题没答：下次买服务时，到底该盯着哪几栏看。

这篇就是把那些分散的诊断结论收成一张采购清单。收敛之后一共五项，顺序不是随便排的，而是按「不合格时后果有多严重、有多难自己补救」排的。前两项不合格基本没法用，第三项决定你能不能跑长任务，后两项影响的是摩擦大小。

顺带处理两个流传极广、也最容易导致买错的说法：延迟越低越好，以及有原生 IP 就等于稳。这两句都不是全错，问题在于它们各自只覆盖了五项里的一小块，却被当成了全部标准。

| 指标       | 不合格时的典型症状         | 优先级 | 自己能不能补救       |
| ---------- | -------------------------- | ------ | -------------------- |
| IP 类型    | 直接提示不可用、进不去     | 高     | 不能，取决于服务商   |
| 出口稳定性 | 掉登录、反复验证、任务中断 | 高     | 部分能，靠客户端锁定 |
| 长连接存活 | 长任务跑到一半断           | 中高   | 部分能，靠协议与规则 |
| 地区匹配   | 功能受限、内容版本不对     | 中     | 换出口地区即可       |
| 共享密度   | 验证码变多、时好时坏       | 中     | 不能，取决于服务商   |

## 指标一：IP 类型——像不像一个真实用户

平台读的不只是这个 IP 登记在哪个国家，还有它属于哪家网络运营者，也就是 ASN。这一项区分的是数据中心带宽和民用宽带：一个普通用户不会从云服务商的机房里访问 AI 网站，而这类判定恰恰是风控最容易做的一刀。

所以「换了美国节点还是不行」经常不是国家选错了，是换到了另一个国家的同一类机房 IP。第二项属性根本没变。

自查很快：

```bash
# 结构示例：确认当前出口的登记归属与所属网络
curl -s https://ipinfo.io/json
```

返回结果里的组织信息如果是常见云厂商，就要有心理准备。这一项的完整判定逻辑和「原生 IP」这个词被用歪的地方，[原生 IP 到底解决了什么问题](/unlock/region-lock/native-ip-unlock-truth/)那篇讲得更细。

## 指标二：出口稳定性——一次会话里换几个 IP

一个正常用户半小时内的出口几乎不变。一条典型代理链路可以在同样时间里变好几次：自动测速策略换线、服务商侧负载均衡重新分配、手机在 Wi-Fi 和蜂窝之间切换。

服务端看到的就是同一份会话凭据突然从另一个地方出现，轻则要求重新验证，重则直接作废登录态。这一项是五项里最容易被误诊的——很多人把它当成账号问题或者平台抽风，实际上是出口跳了。成因和自查方法见[出口 IP 漂移的排查](/unlock/region-lock/ai-exit-ip-drift/)。

选购时该问的是：这个节点名对应的是一台固定出口机，还是一组后端轮换的出口？后者在前台看不出来，只能自己在会话前后各查一次。

## 指标三：长连接存活——能撑住多久的流式输出

聊天是短请求，断一次几乎无感；API 流式输出和命令行工具的长任务是持续数分钟的单条连接，中途任何一次抖动、空闲回收或中转切换都会直接打断它。

跳数越多的中转链路，越容易在这里翻车——每多一跳就多一处可能提前回收空闲连接的中间设备。协议选择也有影响，具体的机理在[长连接、流式输出与节点的三角关系](/unlock/region-lock/openai-api-long-session/)里展开过。

这一项的测法比前两项笨但有效：在同一节点上连续跑两次十分钟以上的长任务，记录是否中断、在第几分钟中断。

## 指标四：地区匹配——和账号对得上吗

出口地区不是越「热门」越好，而是要和你账号的属性、以及你要用的功能对得上。账号侧属性和网络出口分属两层，出口只能改后者。

同一条链路上，网页版可用、App 不可用是常见的，因为 App 还额外受应用商店账号地区的约束。判断顺序应该是先确认账号能用，再挑出口地区，反过来做很容易白花钱。

## 指标五：共享密度——这个 IP 后面挂着多少人

同一个出口 IP 上如果同时挂着几十个账号在跑 AI，这个 IP 的行为特征在平台看来就不像个人用户。结果是验证码变多、限流更早触发、状态时好时坏。

用户侧无法直接查询密度，但有两个间接信号：一是节点在晚高峰明显比白天更容易触发验证；二是同服务商的多个节点表现高度一致，说明整批 IP 的处境相同。低价大流量套餐把成本压下来的位置，往往就包含更高的复用率，这不是道德问题，是定价结构的必然结果。

## 误解一：延迟越低，AI 体验越好

延迟决定的是首字响应，也就是你按下回车到第一个字出现之间那一小段。回复开始滚动之后，速度主要由服务端生成速度和链路吞吐决定，延迟的权重迅速下降。

| 使用场景     | 延迟的影响             | 稳定性的影响     |
| ------------ | ---------------------- | ---------------- |
| 短问答       | 明显，等待感直接来自它 | 较小             |
| 长文档生成   | 只在开头几秒           | 大，中断就要重来 |
| API 流式调用 | 很小                   | 决定性           |
| 命令行长任务 | 几乎无关               | 决定性           |

一条稳定的 150ms 链路，在长任务上通常比一条在 40ms 和 300ms 之间来回跳的链路好用得多。测速软件跑出的峰值数字不反映这种波动，所以它对 AI 场景的参考价值有限。

## 误解二：有原生 IP 就等于稳

原生 IP 只解决第一项。它说明这个 IP 的登记归属和节点位置一致，让你不容易在门口被拦下，但它不承诺这个 IP 在你的会话期间不变，也不承诺它上面只挂着你一个人。

现实中很常见的组合是：原生 IP、进得去、然后每二十分钟掉一次登录。这时候问题在第二项，和第一项无关。把「原生」当成唯一采购标准，就会反复买到这种只过第一关的服务。

## 用这五项做一次横向对照该怎么记录

不记录条件的测试结果没有可比性，第二天复现不出来也说不清是哪里变了。建议固定成一张表，每个候选节点跑一遍。

1. **记录测试条件。** 日期、时段（区分白天与 20:00–23:00）、本地网络类型、客户端与版本。缺了这几项，两次结果之间无法比较。
2. **查一次出口 IP 与 ASN。** 对应指标一，同时作为后面比对的基准值。
3. **跑一次十分钟以上的长任务，结束后再查一次出口 IP。** 两次不一致就是指标二不合格，一致则继续。
4. **记录长任务是否中断、在第几分钟中断。** 对应指标三，连续做两次取更差的一次。
5. **记录期间出现验证的次数。** 对应指标五，晚高峰单独记一组。

| 节点   | 出口 ASN 类型 | 会话前后 IP 是否一致 | 长任务中断 | 验证次数（晚高峰） |
| ------ | ------------- | -------------------- | ---------- | ------------------ |
| 示例 A | 机房          | 否                   | 第 6 分钟  | 2                  |
| 示例 B | 机房          | 是                   | 未中断     | 0                  |

表里的数值是格式示例，不是实测结果；你自己填出来的那一版才有意义。

带着上面五项去看候选，比看宣传语有效得多。下面三家的信息来自品牌公开资料，属于厂商声明，仅用于说明「该对照哪些公开规格」。

| 品牌                            | 开业年份 | 入门价              | 入门流量 | 线路（厂商公开） | AI 相关声明              |
| ------------------------------- | -------- | ------------------- | -------- | ---------------- | ------------------------ |
| [光速云](/reviews/guangsuyun/)  | 2020     | 7.5 元/月(年付折算) | 59GB     | IEPL、内网专线   | 公开资料声明支持 AI 工具 |
| [星岛梦](/reviews/xingdaomeng/) | 2020     | 8 元/月（年付折算） | 60GB     | 内网专线         | 公开资料未明确说明       |
| [灵猫网络](/reviews/lingmao/)   | 2024     | 19 元/月            | 150GB    | 内网专线         | 公开资料未明确说明       |

星岛梦的 8 元是年付折算价，需要一次性支付一年费用，不能和月付价直接比较。灵猫网络 2024 年开业，运营时间短于老牌品牌。三家都只在公开资料里给出了线路类型，而线路类型和上面五项里的任何一项都不是一一对应关系——专线更有利于第三项长连接存活，但不代表第一项和第五项自动达标。

所以合理的做法是：把公开规格当作筛选候选的第一道过滤，然后用月付试一个周期，按上面那张记录表实测。选购层面的通用取舍，[机场选购对照](/compare/how-to-choose-airport/)里有更完整的框架；只想直接看按 AI 场景整理的候选名单，可以去[ChatGPT 场景榜单](/rankings/chatgpt/)。

## 小结

AI 场景的节点标准可以收敛成五项，且顺序固定：IP 类型和出口稳定性决定能不能用，长连接存活决定能不能跑长任务，地区匹配和共享密度决定摩擦大小。延迟只在首字响应上有感，权重排在最后；原生 IP 只过第一关，不能当成唯一依据。选购时先用公开规格过滤候选，再用月付跑一份自己的记录表——这份表比任何宣传语都更能回答「这条链路适不适合我」。
