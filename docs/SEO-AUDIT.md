## 四、问题清单

### P0 —— 已修复

#### P0-1 `/search/` 的三重矛盾索引信号

**现象**:同一个 URL 同时被三种方式对待——

| 位置         | 信号                             |
| ------------ | -------------------------------- |
| `robots.txt` | `Disallow: /search/` —— 禁止抓取 |
| 页面 meta    | `noindex` —— 禁止索引            |
| `sitemap`    | 收录 —— **邀请索引**             |

**为什么是问题**:robots 挡住抓取后,搜索引擎**根本读不到那个 noindex**,却被 sitemap 反复邀请。站长平台会持续报「已提交但被 robots.txt 阻止」,同时消耗抓取预算。

**影响**:不会直接掉索引,但会污染索引覆盖率报告,让真正的问题被淹没。

**修复**:`astro.config.mjs` 的 sitemap filter 增加 `/search` 排除。Sitemap 206 → 205 条。

**验证**:`pnpm seo:check` 的 Sitemap 项会检测「sitemap 含 noindex/禁抓页面」。

---

#### P0-2 结构化数据泄漏年付折算价

**现象**:品牌页的 `Product.offers` 上报裸价格,不带任何计费周期:

```json
"offers": { "@type": "Offer", "price": 7.5, "priceCurrency": "CNY" }
```

**为什么是问题**:7.5 元是**年付折算价**,要一次性付一整年。可见内容里这个数字每次出现都被强制标注「年付折算」(有产物层扫描守着),但**结构化数据是另一条通道**——富媒体结果里会显示成「光速云 ¥7.5」,读者得到的是月付价的错觉,而那个标注根本没跟过去。

这同时违反两条规则:本站自己的价格口径规则,以及防掉索引总指令第十四条「不得伪造价格 / Schema 内容必须与页面可见内容一致」。

**影响**:富媒体结果展示误导性价格。长期看还有被判定为结构化数据与页面不符的风险。

**修复**:年付品牌上报**年度总价**(7.5 → 90)并声明 `billingDuration: 12`;月付品牌上报月价并声明 `1`。两者都用 `UnitPriceSpecification` 显式写明周期:

```json
"offers": {
  "price": 90, "priceCurrency": "CNY",
  "priceSpecification": {
    "@type": "UnitPriceSpecification",
    "price": 90, "billingDuration": 12, "unitCode": "MON",
    "description": "年付套餐总价,需一次性支付一整年,折算每月约 7.5 元"
  }
}
```

**验证**:新增 T7-10c 检查——Offer 必须带 `priceSpecification`,且不得直接使用年付折算价数字。

| 指标                      | 在哪看                                | 为什么                                        |

## 十、复现方式

```bash
pnpm build && pnpm seo:check
```

输出以 `RELEASE_DECISION: READY` 或 `BLOCKED` 结尾。BLOCKED 时会列出问题项,**未通过不得部署**。

首次通过后用 `pnpm seo:accept` 写入页面数量基线,之后每次检查都会与基线比对,变化超过 ±20% 会拦下来人工确认——这条专门防两类事故:内容被误删导致的骤降,以及模板失控导致的骤增。
