## 一、这批证据能证明什么

1. 该品牌在截图所示的时间点发生过一次节点测速,并得到图中显示的结果。
2. 截图中显示的协议为 Shadowsocks 或 VLESS;这只反映本次测试所选节点,不代表该品牌全部节点。
3. 同一张图内可能同时存在速度较高的节点、0B 节点和延迟异常的节点,差异是原始结果的一部分。
4. 不同品牌的测试时间、测试工具与测试界面并不完全一致。

## 二、这批证据不能证明什么

1. 不能证明长期稳定,也不能证明晚高峰始终保持截图中的速度。
2. 不能据此宣称某家是 16 家中最快或最稳定的机场。
3. 不能证明 ChatGPT、Claude、Gemini、Netflix、Disney+ 等服务可以解锁——**本批次根本没有测这些**。
4. 不能证明节点使用 IEPL、IPLC、原生 IP 或住宅 IP;线路属性需要独立来源。
5. 不能证明机场的运营安全、退款政策或是否会跑路。
6. 不能把不同工具、不同协议、不同时间的结果合并成一个总分或排行榜。

以上两组清单已编码在 `src/data/evidence.ts` 的 `ALLOWED_CLAIMS` 与 `PROHIBITED_CLAIMS`,
并由 `src/lib/evidence.test.ts` 断言,不是只写在文档里的约定。

## 三、为什么不能做横向排名

| 维度     | 实际分布                                                 | 后果                                           |
| -------- | -------------------------------------------------------- | ---------------------------------------------- |
| 测试工具 | 14 张 MAI-TEST-BOT 2.0.0-dev,2 张主端 4.3.3 / 喵速 4.7.0 | 两套工具的测量口径与后端不同,数值不可直接比较  |
| 图中协议 | 14 张 Shadowsocks,2 张 VLESS                             | 协议不同会影响握手与吞吐表现                   |
| 测试时刻 | 00:21 → 22:46,横跨全天                                   | 凌晨测的品牌与晚高峰测的品牌不在同一网络环境下 |
| 测试后端 | 珠海联通 5Gbps(多数)/ 9Gbps(2 张)                        | 基础带宽不同                                   |

要做真正的横向比较,必须按指令 §十一 重新组织一批受控测试:统一工具版本、统一后端、
统一地点与运营商、统一协议或按协议分层、统一节点筛选规则、多次重复、明确单位定义,
并用中位数与分位数而非峰值。**当前批次不满足其中任何一条,因此只能作为单品牌的批次记录。**
