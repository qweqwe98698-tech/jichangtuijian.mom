## 二、冲突裁决

### 裁决 1:光速云入门套餐口径(2026-08-18)

**冲突**:第三阶段品牌清单与站上现有数据不一致。16 家中 15 家逐字段相同,仅光速云不同。

| 字段     | 站上现有 | 第三阶段清单 |
| -------- | -------- | ------------ |
| 入门价格 | 17 元/月 | 7.5 元/月    |
| 入门流量 | 110 GB   | 59 GB        |
| 计价口径 | 月付     | 年付折算     |

**裁决:以第三阶段清单为准。** 由用户在 2026-08-18 明确选择。

**已执行的连带修改**:

- `src/data/brands.ts`:光速云改为 `entryPriceCNY: 7.5 / trafficGB: 59 / basis: 'annual-equivalent'`,
  补 `pricing.note` 与 `editorial.caveat`(年付口径必须带说明,由单元测试强制)
- 定位从「老牌综合型 · IEPL · VLESS」改为「老牌综合型 · IEPL · 年付低价」,优缺点重写
- `comparableWith` 从月付同价位品牌改为年付同口径品牌(飞猫云、星岛梦、宇宙云)
- 月付组 14 → 13 家,年付折算组 2 → 3 家
- 首页结论段改为**从品牌数据派生**,不再写死价格(此前写死过一次,数据一变就与规格表脱节)
- 三篇文章中的硬编码价格已同步:`ranking-methodology`(移入年付表)、
  `ai-node-requirements`、`v2rayn-vs-clash-verge`

**评分影响**:光速云单位流量成本 0.155 → 0.127 元/GB,性价比维度 6.9 → 9.9,总分 8.8 → 9.7。
因为性价比是全站 16 家归一化算出的,**其他品牌的得分也随之变化**。
`src/lib/rubric-examples.test.ts` 已同步更新——该测试失败正是提醒同步的机制。

**未解决的疑问**:15 家一致、仅 1 家差异,不像版本新旧问题,更可能是光速云同时存在
17 元/月·110GB 与 7.5 元年付·59GB 两个套餐,而清单更新了"入门档"的指向。
若后续确认两档并存,应在品牌页单独列出月付档并标注付款周期,而不是替换。

### 裁决 2:编辑评分与品牌库排序(2026-08-18)

**冲突**:指令 T4 禁止品牌库出现「综合评分/星级」排序,理由是当前截图不支持横向排名;
但站上已有一套编辑评分体系,并驱动着 9 个场景榜单。

**裁决:保留评分,但品牌库不按分排序。** 由用户在 2026-08-18 明确选择。

**理由与边界**:

- 现有编辑评分**不使用任何测速数据**。五个维度(流量性价比 30% / 线路等级 25% /
  运营时长 15% / 客户端友好度 15% / 场景覆盖 15%)全部取自厂商公开字段,算法公开在
  `/editorial-policy/`,任何人可复算。它与本批截图证据无关,因此不受 T4 那条禁令的直接约束。
- 但 T4 的意图——不制造证据不支持的推荐暗示——仍然适用。因此**新建的品牌库页面
  只提供价格 / 流量 / 开业年份 / 线路类型 / 客户端支持 / 数据状态等客观字段的筛选与排序,
  不提供按总分排序**,也不显示星级。
- 品牌库的 ItemList Schema 不携带 ratingValue 或 aggregateRating。

## 三、证据使用边界(适用于全部页面)

本批 16 张截图的允许与禁止声明已编码在 `src/data/evidence.ts` 的 `ALLOWED_CLAIMS` /
`PROHIBITED_CLAIMS`,并由 `src/lib/evidence.test.ts` 断言。要点:

**可以说**:某品牌在截图所示时间与条件下发生过一次节点测速;图中同时存在高速节点、
0B 节点与异常延迟节点;不同品牌的测试时间与工具不一致。

**不能说**:长期稳定;16 家中最快/最稳;AI 或流媒体解锁(本批根本没测);
节点使用 IEPL/IPLC/原生 IP;运营安全或退款保障;把不同工具协议时间的结果合成总分。
