# 第三阶段交接:T0–T7 做了什么,以及为什么这么做

这份文档写给下一个改这个站的人(可能是几个月后的你自己)。它不复述目录结构——那些看代码更快。它记录的是**那些看代码看不出来的判断**:为什么某个字段是空的、为什么某张图没发、为什么某个排序被刻意做得不好用。

---

## 一、第三阶段的核心问题

这个站是推广站。推广站最容易走的路是:把厂商宣传语抄进正文,配几张测速截图,加个绿色对勾表格,读者看着像评测,实际是软文。

第三阶段做的全部工作,可以概括成一句话:**让「本站测过什么」和「厂商声称什么」在任何一个像素上都不可能被混淆。**

这不是道德姿态,是可持续性问题。抄宣传语的站有无数个,它们互相之间没有区别,也没有理由被信任。区别只能来自「敢说自己不知道什么」。

---

## 二、四层数据模型:每个字段属于哪一层

`src/data/brands.ts` 把品牌信息分成四层。**层级不是分类标签,是可信度声明**,渲染时的视觉待遇完全不同。

| 层           | 含义                         | 谁能写                     | 渲染                      |
| ------------ | ---------------------------- | -------------------------- | ------------------------- |
| `vendor`     | 厂商公开资料里的说法         | 抄自品牌页/清单,不加工     | 警示色 + 「厂商声明」标记 |
| `measured`   | 本站实际测出来的             | 只能来自已放行证据         | **唯一使用成功色的层**    |
| `commercial` | 商业关系、推广链接、支付方式 | 人工核验并记日期           | 中性色 + 披露文案         |
| `editorial`  | 本站的编辑判断与评分         | 由 `src/lib/scoring.ts` 算 | 标注为主观判断            |

外加一个 `evidence` 层(`src/data/evidence.ts`)管证据素材本身的审核状态。

### 三条不能破的规则

1. **vendor 永远不会自动升级成 measured。** 没有代码路径能做这件事。要升级必须显式改 evidence 层并同步改组件——这个摩擦是故意的。
2. **commercial 永远不影响排名。** 评分函数不读 commercial 字段。
3. **mock 数据不进入任何可索引页面、JSON-LD 或排名。** 图表样式文件里的示例解锁数据与拓扑数据只控制视觉,不是事实源。

这三条各有测试锁定,不是靠文档约束。

### 关于空字段

`星岛梦` / `飞猫云` / `灵猫网络` / `极连云` 的 `protocols` 是**空数组**,`唯兔云` 的 `lines` 是**空数组**。

这不是漏填。这些品牌的公开资料**从未说明**协议或线路类型。早期版本里我按同类品牌的常见配置填了 VLESS 和「中转/直连」——那是编造。新品牌清单到手后逐条核对才发现。

空数组经 `protocolLabel()` / `lineLabel()` 渲染为「公开资料未标明」,并有 3 条测试锁住,防止有人「顺手补全」。

**未标明是信息,不是缺陷。**评分函数对空线路给 7.0 分而不是 0 分,因为缺数据不等于质量差,不该被惩罚。

## 三、证据层:16 张图,发了 15 张

`public/evidence/speedtest/2026-08-11/` 存放 16 张原始 PNG。它们是**只读**的:不覆盖、不裁掉时间戳、不改写数值。`verify-release.mjs` 每次都重算 SHA-256 与字节数比对,改过就会失败。

### 为什么可信云那张没发

图里的完整测试日期不清晰。放行条件写死为:

```ts
decision.status === 'approved' && asset.dateConfidence === 'visible-in-image';
```

**两个条件是「与」关系。**即使有人把状态改成 approved,日期条件仍会拦住。这个设计是刻意的——审核状态是人可以随手改的,图像事实不是。

其余 15 张已于 2026-08-18 放行。

### 这批证据不能用来做什么

审计明确记录:测试条件不统一(2 套工具、2 种协议、时段跨越 0–22 时)。因此:

- **不能做严格的跨品牌速度排名**
- 不能做稳定性排名
- 不能从单张截图外推长期表现、AI 可用性、线路类型或安全性

这条限制不只写在内部文档里,也写进了品牌库的排序说明——读者能看到。

## 四、状态词表:为什么只有一个状态是绿色的

`src/data/status.ts` 定义全站统一的状态词汇。最关键的一条:

> **只有 `measured` 的 tone 是 `ok`(成功色)。`vendor` 用警示色。**

行业惯例是给「厂商声明支持」也配个绿勾。一个绿色对勾能把「厂商说支持」变成「已验证支持」,而读者分辨不出差别。所以这条由测试锁定,不是风格偏好。

同理,状态表里不存在 `Operational` / `Stable` / 「正常运行」这类词——它们会被读成「已验证正常」。

### 服务可用性矩阵

`ServiceAvailabilityMatrix.astro` 把 AI 工具与流媒体的可用性拆成**两列**:

- 本站实测:全部 `not-tested`(这批证据根本没测过解锁)
- 厂商声明:`vendor` 或 `unstated`

组件**拒绝接受 `measured` 输入**,有测试守着。等真的做了解锁测试,需要显式改造组件并同步 evidence 层,而不是悄悄填个绿灯。

### 拓扑图

`NetworkPathDiagram.astro` 画的**不是任何一家的真实拓扑**——本站没有线路溯源能力,画具体路径就是编造。它画的是「这类线路在结构上意味着什么」,整图标 Vendor Data,并列出 4 条本站无法证明的事项。

未标明线路的品牌走虚线分支,不会被画成专线。

禁用标签(不经公网 GFW / 隐藏真实 IP / 防 QoS / 抗封锁)由 `FORBIDDEN_TOPOLOGY_LABELS` 列出并全站扫描。

## 五、价格口径:这个站最容易出错的地方

16 家里有 3 家的入门标价是**年付折算价**:飞猫云 7 元 / 光速云 7.5 元 / 星岛梦 8 元。要一次性付一整年才拿得到。

把它们和月付价放进同一个排序,读者会得出「最便宜的只要 7 元」——这是错的,而且是这个行业最常见的误导手法。

### 已经做的事

1. 每次出现都带付款周期标注,由 `verify-release.mjs` 全文扫描强制
2. `formatCostPerGB` 保留完整精度(早期四舍五入到 2 位造成过假并列:灵猫 0.1267 与星岛梦 0.1333 都显示 0.13)
3. 品牌库按标价排序时显示口径警示,选项文案直接写「两种口径混排」
4. 默认排序是可比的**单位流量成本**,不是标价
5. `CROSS_BASIS_PAIRS` 把对比页的生成与「同价位可比品牌」列表解耦,跨口径对比页可以存在,但不会污染同价位推荐

### 验收时仍然发现三处正文违规

即便有以上机制,三篇文章仍写了「月费 7 元」。**规则写了不等于被遵守**,所以最后那道产物层扫描是必要的——它扫的是读者真正拿到的 HTML,不是源码。

Hash 路径 + code 参数。**不要「规范化」它**——不要去掉 `#`、不要把参数移到问号前、不要加 UTM。改了就收不到转化。有测试和产物层检查同时守着。

## 七、内容生产:并行写作的教训

118 篇文章是多智能体并行产出的。第一次尝试的结果是**内容永久丢失**:三个客户端集群的智能体各自决定用 `import-subscription` 这个 slug,互相覆盖,v2rayN 那篇没了。

### 现在的做法:先冻结结构,再写正文

1. `build-manifest.mjs` 从集群定义算出全部结构字段(slug、路径、pillar、relatedSlugs、关键词),冻结进 `docs/CONTENT-MANIFEST.json`
2. 写作智能体**只产出正文**,不许碰结构字段
3. `check-manifest.mjs` 逐篇比对落盘文件与清单

结构漂移不会让构建失败,但会静默产出错误 URL 与断裂内链。所以必须主动检测。

当前:88 篇与清单**零漂移**。

### 去模板化

并行写作的第二个风险是「结构一致 = 内容雷同」。两道门禁:

- `check-profiles.mjs`(T5):品牌档案骨架相似度
- `audit-outline-uniqueness.mjs`(T3):品牌大纲骨架相似度

两者均 0 条警告。注意:**推广披露文案被排除在相似度检查外**——那部分本来就应该一致,反而要求它必须存在。

曾经修过一次跨批次撞车:光年梯与全球云都用了「能查到什么/查不到什么」的骨架,后者重写为单变量受控对比框架。

## 九、踩过的环境坑

| 坑                                               | 表现                                               | 解法                                                         |
| ------------------------------------------------ | -------------------------------------------------- | ------------------------------------------------------------ |
| PowerShell `Set-Content -Encoding utf8` 写 BOM   | frontmatter 解析失败                               | 用 `[System.IO.File]::WriteAllText` + `UTF8Encoding($false)` |
| TypeScript 7                                     | `astro check` 崩溃(缺程序化 API)                   | 锁 TS 6.0.3                                                  |
| `tsconfig` 里 `.astro` 同时在 include 和 exclude | 内容类型不可见                                     | exclude 里删掉                                               |
| `getStaticPaths: GetStaticPaths` 类型注解        | 返回类型被擦除,`Astro.props` 变 unknown(37 个错误) | **不加注解**                                                 |
| `vitest.config.ts` 用 `new URL().pathname`       | Windows 下得到 `/C:/Users/...`                     | 改用 `path.resolve`                                          |
| PowerShell `dist\**\*.html`                      | 不深度递归,计数错误                                | 用 `Get-ChildItem -Recurse`                                  |
| prettier 折行 flow 序列                          | 32 篇被误判内链不足                                | frontmatter 统一块状序列 + 测试锁定                          |

## 十一、如果你要加一个品牌

按顺序做,跳步会在门禁处被拦下:

1. 在 `src/data/brands.ts` 加条目。**只抄公开资料原文**,没说的字段留空数组或 `null`,不要推断
2. 在 `src/data/brand-keywords.ts` 注册关键词(主词 + 5 个次词 + 3 个 GEO 问题)
3. 写 `src/content/brand-profiles/<slug>.md`。骨架可以一致,分析必须逐家不同——`check:profiles` 会查
4. 如果有测速证据:放进 `public/evidence/speedtest/<日期>/`,跑 `pnpm audit:evidence`,然后在 `src/data/evidence.ts` 的 `REVIEW_DECISIONS` 里**逐张**写审核决定
5. 商业信息(推广链接、支付方式)填 `commercial` 层,更新 `COMMERCIAL_VERIFIED_AT`
6. 跑 `pnpm check:all`

**不要做的事**:不要因为「其他家都是 VLESS」就给新品牌填 VLESS;不要因为「看起来是专线」就填 IEPL;不要在没有所有权证明的情况下写「自营」。
